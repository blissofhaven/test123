# Неподтверждённые формулы, коэффициенты и допущения

Дата проверки: **27 августа 2026 года**.

Этот реестр не утверждает, что перечисленные выражения обязательно неверны.
Он фиксирует другое: в текущем проекте не найден применимый официальный
источник с полным названием, обозначением, разделом/формулой и областью
применимости. Ссылка `m.cite("short_circuit")` фактически ведёт к профилю со
статусом `ЗАГЛУШКА` и строкой `source: не задан`.

Для каждого пункта до появления проверенного источника действует формулировка:
**«Источник и корректность формулы не подтверждены».**

## Источники системы и генераторы

| ID | Фактическая реализация | Неподтверждённое допущение |
|---|---|---|
| UA-008 | Для системы: `|Z| = Uср²/Sкз` либо `|Z| = Uср/(√3·Iкз)` | Напряжение перед КЗ принимается равным табличному `Uср`; отдельного коэффициента напряжения `c` и угла ЭДС нет |
| UA-009 | Если X/R источника не задан, принимается `R=0`, `X=|Z|` | Чисто индуктивный эквивалент может завышать ток; допустимость должна определяться исходными данными и целью расчёта |
| UA-010 | При заданном X/R угол Z определяется как `atan(X/R)` | Не хранится знак/диапазон X/R, источник отношения и отдельные R/X для последовательностей |
| UA-011 | Генератор: `X″d = 1000·x″d·Uср²/Sном`, аналогично для `r_pu` | Используется только сверхпереходное сопротивление и табличное `Uср`; внутренняя ЭДС до КЗ, режим нагрузки, переходный процесс и затухание не моделируются |
| UA-012 | Если Sном генератора не задана, она вычисляется как `Pном·1000/cosφ` | Предполагается, что указанные P и cosφ однозначно задают паспортную полную мощность для расчёта КЗ |

Для UA-008…UA-012: **Источник и корректность формулы не подтверждены.**

## Данные, которые хранятся, но не доказывают участие в расчёте

В объектной модели предусмотрены R1/X1, R2/X2, R0/X0, режим нейтрали, группа
соединения и будущие параметры оборудования. Текущий legacy-решатель ТКЗ
использует в основном положительно-последовательное эквивалентное R+jX.
Само наличие поля в JSON не означает, что оно участвует в формуле.

Подпитка КЗ от синхронных и асинхронных двигателей не реализована. Нагрузка
используется расчётами рабочих токов/защит, но не превращается автоматически в
источник КЗ. Отсутствие двигателей в модели должно быть явным условием
применимости результата.

## Матрица поведения при неполных или противоречивых данных

Матрица описывает фактическое поведение на дату аудита. «Блокируется» означает,
что общий вызов `core.engine.run()` получает ошибку входных данных до выдачи
штатного комплекта результатов. «Продолжается» не означает, что результат
инженерно допустим: это лишь наблюдаемая реакция кода.

### Обязательная матрица отсутствующих данных из §22

| Отсутствует | Native Domain / адаптер | Прямой legacy-core | Итоговый статус |
|---|---|---|---|
| Длина линии | `length_mm=None` получает `unconfirmed`; адаптер ставит `calculation_block_reason` | `length_km≤0` блокируется `Network.validate()` | **Расчёт блокируется**, вымышленная длина не подставляется |
| R линии | Для native-сегмента отсутствие R1 вместе с X1 означает неподтверждённый импеданс и blocker | При наличии сечения `r0` подставляется как `ρ/S`; без `r0` и сечения валидация блокирует | Native — **блокировка**; legacy — **ориентировочный fallback** с trace либо блокировка |

Скрытые или условные значения по умолчанию, найденные в этом тракте:

- `Rисточника=0` при отсутствии X/R;
- `Rтрансформатора=0` при отсутствии `Pк`;
- `parallel_count=1` у конструктивного участка;
- ориентировочные `ρ/S` и X линии — только в прямом legacy-пути;
- ближайшее `Uср` при отличии ступени менее 20 %;
- положение CLOSED создаётся редактором для обычного нового switch, но
  топологическое ядро не подменяет им уже существующий native-аппарат с
  отсутствующими explicit/normal данными.

## Что нужно для снятия статуса «не подтверждено»

Для каждого ID требуется:

1. выбрать конкретную расчётную методику и область применения;
2. указать полное название и обозначение действующего документа;
3. сослаться на конкретный раздел/формулу;
4. сопоставить определения величин и единицы с полями программы;
5. выполнить независимый аналитический пример;
6. добавить тест, который не повторяет производственную функцию;
7. зафиксировать версию/хеш методики в расчётном результате.

До выполнения этих условий значения нельзя помечать как нормативно
подтверждённые, даже если они совпали с одним учебником или сторонней
программой.
