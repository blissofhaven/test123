# Аудит численного метода

Дата проверки: **27.08.2026**.

## Фактический алгоритм

1. Из полного активного графа берутся узлы, связанные с общим `GRID`.
2. `TieBranch` и любые ветви с `|Z|<1·10⁻¹² Ом` объединяют узлы.
3. Для оставшихся узлов создаётся плотная комплексная матрица Ybus.
4. Ветви штампуются проводимостью `1/Z`; источники являются ветвями к `GRID`.
5. Выполняется полное `numpy.linalg.inv(Y)`.
6. `Zth` берётся с диагонали Zbus.
7. Ток КЗ вычисляется по модулю Zth.

Это полноценный узловой метод, а не поиск единственного пути. Примеры с
параллельными ветвями, двумя источниками и последовательными участками
подтверждают, что сеть не сворачивается в дерево.

## Положительные свойства

- Используются комплексные `complex128`.
- Нулевые коммутационные ветви объединяются, а не заменяются произвольным
  малым сопротивлением.
- Обрыв связи с источником представлен отсутствием узла в расчётной матрице,
  а не обычным `0 кА`.
- Результат не округляется до завершения решения.

## Подтверждённые ограничения

| ID | Уровень | Наблюдение | Инженерское влияние |
|---|---|---|---|
| `KL-010` | Высокий | Проверяется только `LinAlgError`; `cond(Y)` и остаток решения не вычисляются | Почти вырожденная матрица может вернуть число без признака недостоверности |
| `AUD-SC-003` | Высокий | Нет проверки `isfinite` матрицы и результата | NaN источника прошёл до `Iк3=nan` без ошибки режима |
| `KL-032` | Средний | Фиксированный абсолютный порог `1e-12 Ом` применяется после приведения | Поведение зависит от выбранной ступени; малое ненулевое Z превращается в идеальную связь |
| `AUD-SC-011` | Высокий | `distribution_factor()` возвращает `abs(d)` | Теряются знак, фаза и реальное направление тока ветви |
| `KL-003` | Высокий | Строится и обращается плотная матрица N×N | Память O(N²), время O(N³); 5000 узлов требуют сотни МБ только на одну матрицу |

## Независимый решатель аудита

`tests/calculation_audit/reference_solver.py`:

- не импортирует production core, адаптер или Domain Model;
- самостоятельно штампует Ybus;
- применяет `numpy.linalg.solve(Y, e_k)`, не обращая матрицу целиком;
- сохраняет комплексный коэффициент тока ветви с направлением;
- проверяет конечность входов и решения;
- сообщает `condition_number` для диагностики.

Он предназначен только для малых контрольных моделей и не подключён к GUI.
Строгий `xfail` разворачивает одну и ту же физическую ветвь: независимый
комплексный коэффициент меняет знак, а production в обеих ориентациях
возвращает положительный модуль `1,0`.

«пройден» означает совпадение с записанным ожиданием при текущем прогоне, но не
устанавливает универсальную устойчивость для сетей произвольного размера.

## Повторяемость контрольных примеров

`test_control_example_repeat_and_save_reload_are_identical` охватывает примеры
1–6: повторный расчёт в том же процессе и файловое сохранение/загрузку. Граница
этого доказательства существенна: тест строит legacy `core.Network`, а функция
`io.project.save()` записывает legacy-формат v2, который затем читается через
миграционный путь. Это **не** перезапуск GUI/процесса и **не** сквозной
native-v7 маршрут `Domain → topology → projection → adapter`. Поэтому тест
подтверждает численную повторяемость legacy-пути, но не закрывает требование
реального restart и новой объектной модели.
