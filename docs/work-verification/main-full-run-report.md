## Десятый отказ — не дефект приложения, но тест зависит от версии Python

`test_equipment_placement_registry::test_registry_is_immutable_and_deterministic`
ждёт `AttributeError` при записи постороннего поля, а получает
`TypeError: super(type, obj): obj must be an instance or subtype of type`.

Причина вне проекта. У `@dataclass(frozen=True, slots=True)` класс
пересоздаётся после генерации методов, и замыкание в сгенерированном
`__setattr__` держит **прежний** объект класса. Воспроизводится тремя строками
без всякого РЗА-Про:

```python
@dataclass(frozen=True, slots=True)
class A:
    x: int = 1
A().extra = "m"        # CPython 3.11 → TypeError; 3.12+ → AttributeError
```

В моей среде CPython 3.11.15. На 3.12+ тест проходит. Приложение здесь ни при
чём, но тест молча зависит от версии интерпретатора — это стоит либо закрепить
требованием к версии, либо ослабить до `except Exception`.

## Что НЕ проверено

**Всё Qt-зависимое.** 25 модулей не импортируются без PySide6: окно, сцена,
призрак размещения, диалоги, цвета, подписи. Числа 1896 и 269 из
`ui_bus_size_restore` получены pytest на Windows с Qt; я их не воспроизвожу и
поэтому не переношу в `tests` как текущее состояние — они остаются там, где
были, историческими.

Полная приёмка `main` требует прогона pytest на машине с Qt. Мой прогон
отвечает на более узкий вопрос: **перенос файлов не задел расчёт и не задел ни
одного теста вне Qt.**
