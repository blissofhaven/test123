# Независимая приёмка расчётных изменений этапа 1

Дата: 2026-09-07. Сравнены исходный код из `original-project-backup.zip` и подготовленная копия `work/stage-01/review-tree`. Приёмка ограничена исправлениями полноты МТЗ и условий ТО. Исходный проект, код подготовленной копии и замороженный эталон этим проверяющим не изменялись.

**Результат: четыре изменения эталона обоснованы. Числа контрольных проектов сохранены. Независимые контрпримеры воспроизводят старые дефекты и подтверждают исправленное поведение.**

Исходный код из архива сначала воспроизвёл замороженный эталон с нулём отличий. После исправлений получено ровно четыре добавления проверок полноты; иных отличий нет.

Распределение итоговых статусов не изменилось: 221 OK, 68 FAIL, 25 UNRESOLVED. Это не противоречит исправлению полноты: четыре изменившиеся защиты уже имели доказанный FAIL, а новые проверки отдельно показывают недоказанные условия.

## Каждый из четырёх diff

Во всех случаях добавлен ключ `Полнота: Отстройка ТО от броска намагничивания` в проверках ТО проекта `gtes_sever`. Значения: `value=null`, `required=null`, `status=unresolved`. Счётчики полноты не подставляются вместо токов или коэффициентов чувствительности.

| Ветвь | Полнота броска | Причина |
|---|---|---|
| G1_bt | 0 из 2 | В max и t1off не определены направление включения и токораспределение броска при питании с двух сторон |
| G2_bt | 0 из 2 | Та же причина в max и t1off |
| G3_bt | 0 из 5 | В max, min, t1off, t1off_min — двустороннее питание; в one — не задана конечная положительная кратность i_inrush_ratio |
| G4_bt | 0 из 4 | Двустороннее питание в max, min, t1off, t1off_min |

У всех четырёх исходное поле кратности отсутствует. В многопитаемых режимах проверка останавливается раньше, на неподдержанном токораспределении броска. Поэтому объяснять все четыре diff только отсутствующей кратностью было бы неточно. Ни кратность 1, ни произвольное распределение броска не подставлены. Прежние провалы чувствительности и соответствующие FAIL сохранены.

Подробные новые сообщения находятся в `after/protection_details.json`; машинный diff — `after/against_frozen.json`.

## Независимые контрпримеры до/после

Схемы заданы внешним проверяющим в `independent_counterexamples.py` и рассчитаны отдельными процессами сначала исходным кодом из архива, затем подготовленным кодом. Они отличаются параметрами от добавленных разработчиками тестов. Физические формулы и ожидаемые числа не берутся из функций выбора уставок.

| Случай | До | После | Независимое основание |
|---|---|---|---|
| ТО: min с более сильной топологией | Iрасч=2642.606130705 А; принято 3000 А; выбран nominal max | Iрасч=4210.098807115 А; принято 5000 А; выбран reinforced min | Максимум двух аналитических границ сети R+jX |
| ТО своего трансформатора: бросок определяет | Iрасч=934.059498315 А; принято 1200 А | Iрасч=1891.399481865 А; принято 2400 А | 1.3·14·6300/(√3·35) |
| ТО своего трансформатора без Kбр | Принято 1200 А, OK | Предварительное число сохранено, UNRESOLVED, бросок 0/2 | Нет исходного значения для обязательного условия; Kбр=1 не подставляется |
| МТЗ: успешный радиальный режим и неопределимый идеальный контур | Принято 10 А, OK | Число сохранено, UNRESOLVED, основная зона 1/2 | Ток через один из параллельных идеальных аппаратов не определён однозначно; успешный другой режим не закрывает проверку |

Для первого случая заданы Uрасч=10.5 кВ, линия 8 км с R=0.15 Ом/км и X=0.08 Ом/км. В режиме nominal max источник имеет Sкз=60 МВА; в reinforced min работают параллельно источники 50 и 300 МВА, коэффициент сопротивления линии в min равен 1.2. Поэтому:

`Zmax = 1.2 + j·(0.64 + 10.5²/60) Ом`

`Zmin = 1.44 + j·(0.64 + 10.5²/350) Ом`

`Iграница = 1.2·10500/(√3·|Z|) А`

Границы равны соответственно 2642.606130705 и 4210.098807115 А. При ТТ 500/5 и заданной шкале следующий доступный первичный ток после 4210.098807115 А равен 5000 А. Итоговый FAIL чувствительности в данном случае сохраняется: правильный выбор отстройки не обязан делать защиту пригодной.

Во втором случае паспорт трансформатора — 6300 кВА, 35/6 кВ; Kбр=14, kотс.бр=1.3, ТТ на стороне 35 кВ. Граница броска 1891.399481865 А определяет уставку. При ТТ 300/5 и заданной шкале 40 А вторичных дают 2400 А первичных. Расчётное среднее напряжение ступени не заменяет паспортные 35 кВ при определении номинального тока включаемой обмотки.

Численные ожидаемые значения проверены с относительным допуском 1e-12. Для 17 существующих трансформаторов дополнительно проверено соответствие округлённой текстовой трассы ручной формуле; допуск этой отдельной проверки относится только к показу четырёх значащих цифр и не меняет численных допусков эталона.

## Перенос эталона

Разрешённый состав изменения эталона с точки зрения этой приёмки — **только четыре перечисленных добавления UNRESOLVED-проверок**. Замороженный файл этим проверяющим не обновлялся. Его SHA256 при съёме обоих снимков: `29a8fc8db34a1c5a7cc3972cb178dfdb4b1b64359d0cc8d3cb595a39d7230c38`.

Для штатного журнала подходит основание: «Этап 1: ТО теперь проверяет собственный бросок трансформатора и явно отмечает неполноту неподдержанного двустороннего включения/отсутствующей кратности. В четырёх блочных трансформаторах gtes_sever добавлены UNRESOLVED-проверки; исходные FAIL и все численные уставки, 907 точек КЗ и 760 пар селективности сохранены. Независимые схемы подтверждают учёт сильного min-режима, определяющий собственный бросок и запрет ложного OK при частичной проверке».

## Границы результата

Это инженерная проверка ограниченных дефектов и сохранности расчётных данных. Четыре справочных проекта не воспроизводят сами по себе пропуск более сильного min-режима или частичную ошибку чувствительности; для этого выполнены отдельные контрпримеры. Четыре вида КЗ и токи через ТТ на всех типах сетей этим отчётом заново не аттестованы. Коэффициенты взяты из текущего профиля для воспроизводимого контроля, без заявления об утверждении методики на объекте.

GUI/актуальность поздно пришедшего результата и полный набор тестов находятся вне этой независимой подзадачи. Неподдержанное токораспределение при двустороннем включении здесь честно блокирует полноту; его физическая реализация относится к последующим этапам.

Машинная сводка успешных условий: `acceptance-summary.json`. Скрипты воспроизведения и подробные JSON лежат вне проекта в `work/stage-01`.
