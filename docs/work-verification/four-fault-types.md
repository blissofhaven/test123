# Четыре вида КЗ в выбранном узле — 07.09.2026

## Выполненное расширение

Добавлен отдельный запрос расчёта выбранного повреждения в действующее ядро:
`ShortCircuitSolver.fault_at(node_id, FaultSpec(...))`.

| Вид | Обозначение API/CLI | Повреждённые фазы |
|---|---|---|
| Трёхфазное КЗ | `3ph` | ABC |
| Двухфазное КЗ | `2ph` | BC |
| Однофазное на землю | `1ph_g` | A–земля |
| Двухфазное на землю | `2ph_g` | BC–земля |

Вычисляются комплексные фазные токи и остаточные фазные напряжения в точке
КЗ, составляющие прямой/обратной/нулевой последовательностей, `3I0`,
эквивалентные последовательностные сопротивления и шаги вычисления. Все
сопротивления приводятся к общей ступени с последующим возвратом к ступени
точки КЗ; фазное напряжение в кВ / сопротивление в Ом даёт ток в кА.

Сети последовательностей имеют собственную топологию и объединение идеальных
узлов. Заземлённая сторона трансформатора может представляться шунтом, а
передача нулевой последовательности — разрывом; известный барьер не требует
параметров элементов за ним. Учтён противоположный знак фазового сдвига в
обратной последовательности. Отсутствие нужных исходных данных даёт явную
причину недоступности конкретного вида КЗ.

В GUI: «Анализ и расчёты» → выбрать объект/узел → нижняя вкладка «КЗ» →
выбрать вид повреждения. Инспектор и нижняя панель используют один выбор.
В пользовательском интерфейсе рассматривается металлическое КЗ; API также
принимает сопротивления фазных плеч и общего соединения с землёй.

В CLI, из корня проекта:

```text
python -m rza_calc rza_calc/examples/four_fault_types.json sc --fault-type 2ph_g --node FAULT --mode max
```

Другие значения `--fault-type`: `3ph`, `2ph`, `1ph_g`. Результат доступен —
код 0, не рассчитан с явной причиной — код 3; ошибочный запрос — код 2.
Обычная команда `sc` сохраняет прежний совместимый вывод.

## Исходные данные

Абсолютные `r2_ohm/x2_ohm`, `r0_ohm/x0_ohm` задаются на явно указанном
`sequence_reference_kv`. Эти величины общие для заданных режимов; программа
не выводит Z2/Z0 из Sкз max/min. Если нужен один и тот же эквивалент прямой и
обратной последовательности, это отдельное явное допущение
`negative_sequence_equal_positive=true`, а не автоматическая догадка.

Для линий сохранены канонические `r2_ohm_per_km/x2_ohm_per_km` и
`r0_ohm_per_km/x0_ohm_per_km`. Они учитывают длину и число параллельных цепей;
для режима min к сопротивлению проводника применяется температурный
коэффициент действующего профиля. Составная линия получает эквивалент лишь
при полной паре параметров каждого участка. Несовместимые схемы нулевой
последовательности участков не превращаются молча в обычную проводящую линию.

**Исторические `LineBranch.r0/x0` по-прежнему обозначают удельные R/X прямой
последовательности.** Их смысл не менялся. `GeneratorBranch.xd2` по-прежнему
означает сверхпереходное x″d, а не сопротивление обратной последовательности.

`zero_sequence_connection` задаёт явную эквивалентную схему:

- `series`: связь двух концов;
- `from_ground`: шунт первого конца к опорному узлу, передачи ко второму нет;
- `to_ground`: шунт второго конца, передачи к первому нет;
- `blocked`: нет передачи/шунта в этом эквиваленте.

**Заданное Z0 уже включает все применимые 3Zn. Повторного добавления
сопротивления нейтрали нет.** Это ручной эквивалент, а не автоматическое
распознавание схемы обмоток по строке группы. Для несимметричного КЗ
трансформатор требует явного `sequence_phase_shift_deg`, включая явный 0°;
положительное значение — сдвиг от первого конца ко второму.

Поля сохраняются в проекте v7 и входят в модель. Отдельного мастера ввода
последовательностных схем и автоматического каталога паспортных Z0/Z2 этот
этап не добавляет. Проверочный пример содержит все нужные значения; они
синтетические и прямо помечены как контрольные.

## Контрольный пример

`rza_calc/examples/four_fault_types.json`: источник, линия 2 км, узлы `BUS`
и `FAULT`, режимы `max`/`min`. После сохранения и повторного открытия все
16 сочетаний двух узлов, двух режимов и четырёх повреждений дают конечные
результаты. Для `FAULT/max` модули фазных токов:

| Вид | IA, кА | IB, кА | IC, кА |
|---|---:|---:|---:|
| 3ph | 13.791707 | 13.791707 | 13.791707 |
| 2ph | 0 | 10.369650 | 10.369650 |
| 1ph_g | 7.284125 | 0 | 0 |
| 2ph_g | 0 | 11.288267 | 10.703433 |

Округлённый ноль в таблице допускает остаток машинной арифметики порядка
10⁻¹⁵. Фазные токи двух повреждённых фаз при BC–земля не обязаны иметь
одинаковый модуль при разных углах последовательностных сопротивлений.

## Проверки

Формулы проверяются независимым решением фазных граничных условий, а не
повторением производственных формул. Покрыты четыре металлических КЗ,
неравные Z1/Z2/Z0, сопротивления фазных плеч и земли, KCL,
`IA+IB+IC=3I0`, отсутствующие и некорректные параметры, численные крайние
значения. Сетевые тесты проверяют линии, температурный режим, приведение
напряжений, острова, идеальные выключатели, заземлённый эквивалент
трансформатора и фазовые сдвиги.

Отдельная проверка выявила и устранила потерю диагонального вклада фазового
трансформатора после объединения узлов идеальной перемычкой, лишний запрос
Z0 за барьером трансформатора и отклонение чисто реактивного результата из-за
отрицательного R порядка 10⁻¹⁷ Ом. Существенное отрицательное сопротивление
по-прежнему отклоняется. На прежней «Северной» отличие нового и старого
трёхфазного тока в контрольной точке — около 6,12·10⁻¹⁶ кА.

Финальный объединённый прогон в действующей рабочей копии: **497 passed
за 34,10 с**, включая расчётный аудит, совпадение замороженного эталона,
расчётные паспорта, формат проектов, адаптер, GUI и CLI. Отдельная проверка
формата Windows-запуска: **1 passed**; `ЗАПУСК.bat --smoke-test` завершился
с кодом 0 без ошибок в режиме Qt offscreen. Визуальное открытие окна
на рабочем столе этим запуском не подтверждается.

Добавление необязательных полей последовательностей сохраняет прежний
электрический отпечаток проекта, пока новые данные не заданы. Явно
заданные значения входят в отпечаток и актуальность расчётного паспорта.
Замороженный эталон и его журнал не изменялись. Полная приёмка всех старых
GUI/нагрузочных сценариев этими проверками не заявляется.

## Границы результата

1. Это расчёт четырёх видов повреждения **в заданном узле** симметричной
   исходной сети при явно заданных эквивалентах. Предаварийное напряжение
   задаётся; установившийся нагрузочный режим этим модулем не решается.
2. Расчёт токов через все аппараты/ТТ по отдельным последовательностям и
   автоматический перенос новых токов в МТЗ/ТО/ОЗЗ не выполнены. Старый
   `at()` сохраняет оценку двухфазного тока при Z2=Z1 для совместимости.
3. Ёмкости сети, компенсация нейтрали, взаимная индукция линий, подпитка
   двигателей, ударный/апериодический ток и интеграл Джоуля этим
   расширением не рассчитываются. Если у точки нет пути нулевой последовательности, модуль
   сообщает, что для такой сети нужен отдельный учёт, вместо ложного нуля.
4. Нет автоматического вывода всех схем 2W/3W, автотрансформаторов и
   нейтралей из паспортных групп. Для новых несимметричных расчётов нужны
   обоснованные эквиваленты. Идеальный трансформатор со сдвигом фаз и
   нулевым сопротивлением явно не поддержан.
5. Три ранее найденных дефекта **расчётов защит** повторно воспроизведены:
   исключение режима `min` из отстройки ТО, пропуск собственного броска
   трансформатора, итоговое OK МТЗ при непроверенном режиме. Настоящее
   расширение видов ТКЗ не объявляется их исправлением. Они остаются
   отдельными приоритетными исправлениями; численный эталон не подменялся.
6. Типовой профиль методики не утверждается автоматически. Инженерная
   приёмка конкретного объекта требует проверенных исходных данных и
   независимой сверки постановки и результата.
