# Ортогональная маршрутизация

## Граница ответственности

Qt-независимый модуль `rza_calc.editor.orthogonal_routing` работает только с
графическими координатами. Он не импортирует `ElectricalModel`, не создаёт
узлы и подключения и не вычисляет физическую длину. Результат маршрутизации
становится сохраняемой геометрией `DiagramRoute` только после успешной команды
редактора.

Предварительный маршрут при движении мыши является временным изображением. Он
не изменяет `ProjectData`, revision документа или историю undo/redo.

## Входные данные

`RoutingRequest` содержит:

- начальную и конечную `RouteVertex`;
- при необходимости направления выхода из портов;
- обязательные промежуточные пользовательские точки;
- локальные прямоугольные препятствия;
- графический зазор `clearance`;
- длину графического выхода из порта `port_stub`.

Зазор и короткий выход из порта измеряются в координатах холста. Это параметры изображения, а не
метры, километры или сопротивление линии.

## Локальный алгоритм

`build_orthogonal_route()` строит небольшой набор детерминированных
манхэттенских кандидатов между соседними обязательными точками:

1. прямой сегмент, если точки уже лежат на одной оси;
2. два варианта с одним поворотом;
3. варианты через средние координаты;
4. варианты вдоль границ локальных препятствий с учётом `clearance`.

Если у порта задано направление, сначала добавляется короткий ортогональный
stub. Кандидаты сравниваются по кортежу:

1. число пересечённых препятствий;
2. манхэттенская длина с штрафом за повороты;
3. число поворотов;
4. детерминированный порядок координат при равенстве.

Это локальный маршрутизатор, а не глобальная автоматическая раскладка всей
подстанции. Его задача — быстро перестроить затронутую трассу.

## Ручные точки

Точки `source=user, pinned=true` являются обязательными промежуточными целями.
Алгоритм строит отдельный ортогональный участок между каждой парой таких целей
и не удаляет их как «лишние».

`normalize_route()`:

- объединяет совпавшие точки без потери пользовательского признака;
- вставляет ортогональный угол вместо диагонального сегмента;
- удаляет только незакреплённые автоматические коллинеарные точки;
- сохраняет пользовательскую точку даже на прямом участке.

В уже сохранённую трассу пользователь добавляет точку контекстным действием
«Добавить точку маршрута». Редактор вставляет закреплённую точку в ближайший
сегмент и локально перестраивает полилинию. При переносе ручной точки холст
показывает временную перестройку, а затем одна команда заменяет весь набор
`RouteWaypoint` и формирует один шаг undo. Ручную точку можно удалить её
контекстным действием.

Выделенная трасса также показывает маркеры достаточно длинных внутренних
сегментов. Перетаскивание сдвигает сегмент только поперёк его оси, превращает
два соседних угла в закреплённые пользовательские точки и сохраняет строгую
ортогональность. Первый и последний сегменты исключены: они задаются
привязками концов и для физической линии изменяются операцией переподключения.
Фиксация переноса — одна графическая команда; электрическая модель, физическая
длина и активная топология не меняются.

## Препятствия и поиск цели

Холст запрашивает только локальные графические элементы рядом с курсором и
формирует `RoutingObstacle` из их ограничивающих прямоугольников. Поиск порта
использует spatial index `QGraphicsScene` и допуск, заданный в экранных
пикселях. Поэтому область захвата остаётся визуально одинаковой при изменении
масштаба.

Линии не считаются препятствиями, создающими электрическую связь. Их простое
пересечение допустимо и не создаёт `ElectricalNode`. Электрическое действие
возникает только после явного выбора совместимого порта, шины, узла либо
команды разделения физической линии.

## Перемещение оборудования

Во время перетаскивания перестраивается предварительный вид только трасс,
инцидентных перемещаемому
представлению. Остальные маршруты и электрическая модель не пересобираются.
После отпускания мыши контроллер одной атомарной командой фиксирует новое
положение и конечные геометрии затронутых трасс.

У выбранной физической трассы отдельные экранные маркеры начала и конца
запускают переподключение её реального порта. Во время перетаскивания работает
тот же временный ортогональный маршрут и подсветка совместимости, а после
завершения `reconnect_port()` одной командой обновляет электрический узел,
привязку конца и сохраняемую геометрию. ID ветви, порта, подключения и самой
трассы сохраняются. Отмена через `Esc` не создаёт изменений проекта.

`LocalRouteCache` адресует результат парой `route_id + RoutingRequest` и умеет
инвалидировать одну трассу. Полная очистка предназначена для смены документа
или глобального изменения графических препятствий.

## Ошибки и резервный сценарий

Маршрутизатор всегда возвращает ортогональную полилинию, но наличие пересечения
препятствия отражается в оценке кандидата. Если полностью свободный путь в
локальном наборе не найден, UI не должен молча менять электрическое
подключение: пользователь видит предварительный маршрут и может добавить
ручную точку либо
переместить объект.

Нулевые сегменты, `NaN`, `Infinity` и повреждённые сохраняемые трассы
отвергаются доменной моделью и кодеком diagram v2.

## Методика проверки производительности

Измерения выполняются на фиксированном воспроизводимом проекте не менее чем с
1000 объектами, 1500 электрическими соединениями, 200 точками ответвлений, 50
реклоузерами и большим числом ортогональных сегментов.

Автоматически измеряются монотонными часами после одного прогрева:

- построение локальной трассы без препятствий и с локальными препятствиями;
- попадание в кэш и перестройка одной трассы после сброса её кэша;
- локальная проверка топологии;
- сохранение v7 и повторное открытие.

Для каждого действия фиксируются медиана, 95-й процентиль и максимум серии, а
также версия Python/Qt, ОС, процессор, размер JSON и точное число сущностей.

Интерактивные показатели измеряются отдельно в GUI:

- задержка появления предварительного маршрута после начала линии;
- задержка фиксации соединения;
- время кадра при масштабировании и панорамировании;
- время предварительного просмотра и фиксации при перетаскивании одного
  аппарата с несколькими инцидентными трассами.

Проверка считается некорректной, если в измерение попали запуск приложения,
первый импорт модулей или антивирусное сканирование временного файла. До
получения чисел оптимизации не считаются доказанными. Каждое движение не должно
перестраивать весь `ElectricalModel` или все трассы проекта.
