# Последовательная вставка оборудования в линию

## Общий контракт

Последовательная вставка не является особенностью картинки реклоузера.
`ElectricalModel.insert_series_equipment_in_line()` автоматически работает с
любым зарегистрированным двухпортовым типом, который явно содержит capability
`placement.inline_series`. Тип с `placement.manual_selection` допускается
только когда вызывающая команда передала
`manual_placement_confirmed=True` после явного выбора пользователя; значение
по умолчанию `False` блокирует вставку.

Вход операции включает:

- ID разрезаемого `LineSection`;
- физическое положение `offset_mm` либо явное `None`;
- `EquipmentTypeId` и версию определения;
- имя и параметры экземпляра;
- при необходимости — явную пару `terminal_roles`;
- явное подтверждение ручного сценария для `placement.manual_selection`;
- постоянные ID для воспроизводимых тестов и миграций.

Тип, имя, `behavior_key`, SVG-символ и число нарисованных выводов не дают
неявного разрешения на вставку. Определение должно иметь ровно два
электрических порта, а выбранные роли должны совпадать с ними без повторов.

## Электрический результат

```text
A -- Sleft -- J1 -- [ equipment ] -- J2 -- Sright -- B
```

Создаются именно два различных терминальных узла:

- левый участок и первый выбранный порт подключаются к `J1`;
- второй выбранный порт и правый участок подключаются к `J2`;
- аппарат остаётся самостоятельным `EquipmentInstance` со своими ID,
  параметрами и состоянием.

Один общий узел с обеих сторон запрещён, потому что создал бы обход аппарата.
Для коммутационного оборудования состояние `OPEN` исключает переход через
аппарат из активной топологии, но не удаляет сам объект.

## Логическая линия и фидер

Строгая `LogicalLine` не перескакивает через отдельный аппарат. После вставки:

- левая часть остаётся в исходной логической линии;
- правая часть получает новую `LogicalLine`;
- обе части сохраняют общий `FeederId`;
- конструктивные участки остаются в исходном порядке.

Экземпляр получает типизированный маркер `line_insertion` с видом
`inline_series`, типом и версией оборудования, ролями портов, обеими
логическими линиями, обоими узлами, фидером и физическим положением. Маркер
также хранит `manual_placement_confirmed`. Он нужен для строгой обратной
операции и не заменяет реальные порты и соединения.

## Обратная операция

`remove_series_equipment_from_line()` является симметричной доменной
командой. Она допускается только когда:

- маркер `line_insertion` цел и соответствует фактическому типу и версии;
- для типа с `placement.manual_selection` в маркере сохранено явное
  `manual_placement_confirmed=True`;
- аппарат по-прежнему имеет два ожидаемых порта в сохранённом порядке;
- каждый служебный узел соединяет только соседний участок и этот аппарат;
- обе части имеют один `FeederId` и совместимые общие свойства линии;
- их физические данные можно объединить без потери порядка и смысла.

При неоднозначности команда завершается ошибкой без мутации. Удаление
произвольного двухпортового объекта не пытается угадывать, был ли он когда-то
вставлен в линию.

Существующие `insert_recloser_in_line()` и `remove_recloser_from_line()`
остаются совместимыми специализированными входами для реклоузера, но общий
архитектурный закон задаёт парные операции вставки и удаления.

## Проектная команда редактора

`ProjectEditorController.insert_series_equipment()` выбирает только
`INLINE_SERIES` через рабочий `EquipmentPlacementRegistry.for_model()`,
вызывает доменную вставку, создаёт представление аппарата и две физические
трассы. `ProjectEditorController.remove_series_equipment_from_line()`
проверяет обе трассы, подготавливает безопасный ID объединённой ветви,
вызывает доменное удаление и восстанавливает одну трассу.

Таким образом, контроллер отвечает за диаграмму, каталожные снимки и один шаг
истории, а `ElectricalModel` — за порты, узлы, линии, маркер вставки и
электрические инварианты. Ручной `MANUAL_SELECTION` не запускается этим
автоматическим контроллерным сценарием.

## Каталожные снимки и история

На уровне `ProjectEditorController` привязка исходного участка копируется на
обе части. При обратном объединении допустимы либо отсутствие обеих
привязок, либо две полностью одинаковые привязки без учёта старого
`equipment_id`. Смешение «есть/нет» или различающиеся снимки и переопределения
блокируют объединение.

Электрическая операция, трассы, представление аппарата и перенос каталожных
привязок входят в один `ProjectCommandHistory` step. Предварительный просмотр
положения аппарата не входит в модель; координаты символа не определяют
`offset_mm`.

## Неподтверждённое положение

Если физическая длина исходной ветви неизвестна, допускается только
`offset_mm=None`. Обе половины сохраняют явное неподтверждённое происхождение.
Топология и состояние аппарата редактируются, но расчёт блокируется до ввода
достоверной длины и расчётных параметров.
