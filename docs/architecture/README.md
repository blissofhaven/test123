# Архитектура RZA Calc

Статус документации: Этапы 0, 1, 2, контрольный Этап 2.5 и базовый редактор
Этапа 3 завершены. Этап 4 добавляет электрические соединения, отдельные
ортогональные трассы и формат проекта v7; Этап 5 не начат.

Единственным источником истины для электрического оборудования и связности
является `ElectricalModel`: оборудование, порты, электрические узлы, явные
подключения и изменения именованных режимов. Координаты, SVG, подписи,
графические пересечения и точки поворота не определяют электрическую сеть.

Формат проекта v7 сохраняет электрическую модель вместе с независимыми от неё
графическими представлениями, проектными снимками каталога и журналом
миграций. Активная топология и расчётная проекция строятся автоматически и
доступны только для чтения.

```text
project v7
├─ electrical_model / ElectricalModel        источник электрической истины
│  ├─ equipment + ports
│  ├─ electrical_nodes + connections
│  ├─ logical_lines + line_sections
│  │                    └─ construction_segments
│  └─ operating_states (position + availability)
├─ diagram v2 / DiagramDocument              страницы и изображения по ID
│  ├─ DiagramPage
│  ├─ GraphicalRepresentation
│  └─ DiagramRoute + RouteWaypoint + endpoint anchors
├─ catalog_snapshots / ProjectCatalogSnapshots
│  └─ CatalogBinding + CatalogEntrySnapshot + ParameterOverride
├─ migration_journal                         история преобразований формата
├─ user_catalog                              встроенные записи пользователя
└─ structure                                 переходная legacy-навигация
       │
       ├─ TopologyEngine.compile(state)
       │      └─ immutable TopologySnapshot
       ├─ CalculationProjectionBuilder.build(...)
       │      └─ immutable CalculationProjection
       └─ adapt_to_calculation(ElectricalModel)
              └─ новый core.Network для каждого расчётного view

builtin SystemCatalog                        только чтение, вне файла проекта
```

`TopologySnapshot`, `CalculationProjection` и `core.Network` являются
производными представлениями. Обратной синхронизации из них в
`ElectricalModel` нет. Совместимый `adapt_to_calculation()` пока строит
`core.Network` непосредственно из той же проверенной канонической модели, а не
из `CalculationProjection`; это намеренная граница совместимости, а не вторая
редактируемая сеть.

`import_legacy_network()` используется только при открытии проектов старых
версий. Пользовательские названия, порядок записей JSON и графическая геометрия
не применяются как внутренние ключи или признаки соединения.

## Реализованный фундамент Этапа 2.5

- `LineSection` остаётся электрической ветвью между соседними узлами и хранит
  упорядоченные `LineConstructionSegment`; её физическая длина является суммой
  подтверждённых длин только когда известны все конструктивные участки;
- разбиение линии переносит или физически делит конструктивные участки, а
  однозначное удаление отпайки объединяет их без потери порядка;
- `CalculationProjectionBuilder` детерминированно строит доступные только для
  чтения расчётные узлы и ветви; трёхобмоточный трансформатор создаёт внутренний
  узел звезды и три ветви;
- `DiagramDocument` сохраняет страницы и графические представления, причём
  один `ElectricalNodeId` может отображаться на любом числе страниц;
- каждый системный, пользовательский и проектный каталог имеет постоянный
  `CatalogId`; `ProjectCatalogSnapshots` хранит использованные версии записей,
  их исходный каталог, привязки экземпляров и явные переопределения параметров;
- формат v7 сохраняет конструктивные участки, диаграмму v2, каталожные снимки и
  журнал миграций; преобразование старого файла сопровождается резервной
  копией и атомарной записью;
- `ElectricalModelMemento` и `CommandHistory` обеспечивают атомарное выполнение,
  отмену и повтор сложной электрической команды;
- проверки целостности охватывают новые идентификаторы и ссылки графических и
  каталожных объектов;
- `ElectricalNodeFaultLocation` и `LineFaultLocation` адресуют будущее место КЗ
  узлом либо физическим расстоянием внутри ветви, не используя пиксели;
- реклоузер остаётся отдельным двухпортовым оборудованием: его состояние
  изменяет активный путь, но не удаляет сам объект и не смешивается с будущими
  параметрами РЗА.

## Реализованный редактор Этапа 3

- современный `QGraphicsScene`-холст напрямую отображает `DiagramDocument`;
- `ProjectEditorController` атомарно изменяет электрическую, графическую и
  каталожную части проекта и предоставляет единый undo/redo;
- работают библиотека базовых элементов, выделение, групповое перемещение,
  копирование, безопасное удаление, свойства, zoom/pan, сетка и привязка;
- режим анализа блокирует геометрию, но оставляет выбор и переключение;
- рабочее место и геометрия сохраняются в формате v7 через обратно совместимые
  extensions;
- прежний SVG-анализ сохранён отдельной вкладкой.

## Фундамент Этапа 4

- Diagram v2 хранит отдельные трассы, постоянные ID точек и явные привязки
  концов, не смешивая их с электрической топологией;
- графическое соединение одного узла и физическая ветвь оборудования имеют
  разные строгие контракты;
- ручные и автоматические точки маршрута сохраняются раздельно, а физическая
  длина никогда не выводится из координат;
- публичные атомарные команды создают физическую ВЛ/КЛ, разделяют её по
  подтверждённому расстоянию, подтверждают длину, создают и удаляют отпайку;
- контекстная команда «Добавить отпайку» после ввода физического положения
  запускает временное рисование боковой ВЛ/КЛ; ручные точки, `Enter`,
  `Backspace` и `Esc` работают до единственной завершающей транзакции;
- сохранённая трасса поддерживает добавление, перенос и удаление ручной точки,
  а также поперечное перемещение внутреннего сегмента одним графическим шагом
  undo без изменения топологии;
- экранные маркеры концов физической ветви позволяют переподключить реальный
  порт с сохранением ID оборудования, порта, подключения и трассы;
- вставка реклоузера создаёт два разных узла и две части с общим `FeederId`,
  а безопасное удаление восстанавливает целую линию только при однозначных
  неизменённых служебных узлах;
- реклоузер вставляется как контекстной командой ВЛ/КЛ, так и перетаскиванием
  элемента из библиотеки на физическую трассу; удаление вставки доступно в
  контекстном меню символа;
- контекстное удаление трассы согласованно удаляет адресованные электрические
  подключения либо физический `LineSection`, а undo восстанавливает графику и
  электрические ID;
- миграция v6→v7 преобразует только однозначные старые трассы, сохраняет
  неоднозначную геометрию для проверки и создаёт backup при перезаписи;
- целостный проект с неподтверждёнными физическими данными сохраняется, но
  `require_calculation_ready()` блокирует расчёт;
- ошибки и предупреждения видны встроенными значками у объектов и трасс, а
  нижняя панель и режим разработчика показывают фактический статус адаптера
  `core.Network`.

## Что остаётся за границей

Этап 5 не начат. Полноценный межсхемный редактор, глобальная автоматическая
раскладка и независимые расчётные подсистемы остаются будущей работой.

Этап 2.5 также не добавляет расчёт токов короткого замыкания, новые формулы
последовательностей, расчёт уставок, алгоритмы АПВ или модель результатов.
Каталожный фундамент не включает браузер и редактор справочника, промышленное
наполнение или онлайн-обновление. Существующий SVG-viewer,
`ProjectStructure`, `core.Network` и его собственные топологические функции
остаются переходными либо совместимыми компонентами.
