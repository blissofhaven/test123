# Модель выбора в редакторе

## Граница модели

Выбор — это краткоживущее GUI-состояние графического представления.
Оно не является состоянием электрического объекта, не меняет топологию,
не входит в расчётный fingerprint и не сохраняется в файле проекта.

Для объектов схемы ключом выбора служит `GraphicalRepresentationId`, а не
имя, `EquipmentId` или координата. Трассы имеют отдельный `DiagramRouteId`.

## Жесты выбора

| Жест | Текущее поведение |
|---|---|
| ЛКМ по объекту | выбрать объект; повторный щелчок не снимает выбор |
| ЛКМ по свободному месту | снять выбор в обычном `SELECT` |
| `Ctrl` + ЛКМ | инвертировать выбор одного объекта |
| `Shift` + ЛКМ | добавить объект к выбору |
| рамка по свободному полю | выбрать пересечённые `shape()` объектов |
| `Ctrl+A` | выбрать все графические представления текущей страницы |
| двойной щелчок | сохранить/установить выбор и открыть свойства |
| `Enter` | открыть свойства первого выбранного объекта или трассы |
| `Esc` | снять выбор, если нет более приоритетной активной операции |

При нажатии ЛКМ на свободном поле общая машина переходит в
`MARQUEE_SELECT`, а при отпускании возвращается в `SELECT`. Этот переход
выполняется и для короткого щелчка без протягивания рамки.

Порт имеет собственную семантику: в режиме редактирования нажатие на
`ElectricalPortItem` начинает создание или переподключение провода, а не
обычный выбор оборудования.

## Синхронизация рабочего места

`DiagramGraphicsScene` испускает кортеж выбранных
`GraphicalRepresentationId`. `EditorWorkspaceWidget` использует его, чтобы
согласованно обновить:

- дерево проекта;
- панель свойств;
- счётчик выбранных объектов в панели команд и нижней диагностической панели.

Изменение только выбора не изменяет проект. Поэтому обработчики выбора с
холста и из дерева не запускают повторную полную проверку проекта и не
перестраивают список проблем: они синхронизируют дерево и Inspector, затем
обновляют только строку `Выбрано: N`. Полная проверка остаётся частью явной
команды проверки и обновлений, вызванных изменением проекта.

Массовый выбор выполняется пакетно. Пока сцена очищает прежний выбор и
устанавливает состояние отдельных `DiagramObjectItem`, промежуточные события
синхронизации подавляются. После завершения испускается один итоговый сигнал с
полным набором ID. Этот контракт используется для `Ctrl+A`, команды
«Выбрать объекты того же типа» и синхронизации выбора из дерева; он не допускает
последовательного обновления рабочего места для каждого из сотен объектов.

Выбор в дереве вызывает обратную синхронизацию: холст при необходимости
открывает страницу, выбирает представление и прокручивает его в видимую
область. При обновлении `DiagramDocument` сцена по возможности
восстанавливает выбор по тому же ID.

## Визуальные состояния

`DiagramObjectItem` не подменяет hover выбором:

- hover — слабая точечная голубая рамка, видимая только под курсором;
- selected — устойчивые светлый halo, синяя штриховая рамка и центральная
  точка;
- compatible/incompatible target — отдельная зелёная/красная обратная связь
  инструмента соединения.

Для двух и более выбранных `DiagramObjectItem` сцена добавляет общую
штриховую рамку. Она не принимает события мыши и не участвует в проверке
коллизий.

## Режим «Анализ»

В режиме «Анализ» объекты нельзя перемещать и вращать, но их можно
выбирать, просматривать свойства и использовать выбор для диагностики.
Inspector остаётся заполненным для выбранного объекта.

Изменения геометрии в этом режиме заблокированы. Действия undo/redo на панели
команд отключены; сочетания `Ctrl+Z`, `Ctrl+Y`, `Ctrl+Shift+Z` и прямые вызовы
GUI-методов отмены/повтора также не передают команду контроллеру. При такой
отклонённой попытке выбор и открытые свойства не теряются.

## Текущие ограничения

- Основной сигнал синхронизации рабочего места содержит только ID
  графических представлений. Выбор трассы не синхронизируется с деревом
  как самостоятельная сущность.
- Двойной щелчок по физической трассе открывает свойства связанного
  оборудования, если для него найдено представление. Для чисто графической
  трассы отдельная форма свойств не реализована.
- Общая рамка группы строится только по `DiagramObjectItem`, а не по трассам.
- Выбор не входит в undo/redo; история хранит проектные команды.

Проверки жестов и различия hover/selected находятся в
`tests/test_ui_interaction_gui.py`. Пакетный сигнал выбора, отсутствие полной
повторной валидации при чистом изменении выбора и ограничения режима «Анализ»
проверяются в `tests/test_ui_interaction_regressions.py`.

Связанное решение: [ADR-024](decisions/ADR-024-hover-vs-selected.md).
