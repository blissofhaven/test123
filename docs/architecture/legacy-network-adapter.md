# Односторонний адаптер к `core.Network`

## Назначение границы

`core.Network` нужен прежнему расчётному коду и старым представлениям. Он не
является моделью редактора и не участвует в командах соединения.

Разрешённое направление данных:

```text
ElectricalModel
    -> validate_integrity()
    -> необязательный совместимый TopologySnapshot
    -> adapt_to_calculation()
    -> новый core.Network + диагностика + таблица трассировки ID
```

Обратной синхронизации нет. Изменение DTO `core.Network`, его узлов, ветвей или
графики не записывается в `ElectricalModel`. Модули `rza_calc.editor` и новый
`rza_calc.gui.editor_scene` не импортируют `core.Network`.

Решение закреплено в
[ADR-015](decisions/ADR-015-one-way-core-network-adapter.md).

## Когда строится производное представление

`ProjectData` хранит номер редакции, для которой было построено совместимое
представление.
Доступ к `network` или `adapter_diagnostics` после изменения
`ElectricalModel.revision` лениво вызывает `refresh_calculation_view()` под
блокировкой. Метод строит новый результат на фиксированной редакции и
отклоняет ситуацию, когда модель изменилась во время построения.

Это означает, что перемещение символа либо точки маршрута не перестраивает
`core.Network`: такие команды не меняют электрическую редакцию. Успешное
электрическое изменение сбрасывает прежнее представление, а следующий доступ строит
его заново.

## Предварительная проверка

Адаптер сначала выполняет `ElectricalModel.validate_integrity()`. При передаче
`TopologySnapshot` дополнительно проверяются identity модели и revision.
Блокирующие диагностики snapshot, например обязательный неподключённый порт,
конфликт напряжений или неоднозначное положение аппарата, преобразуются в
ошибки адаптера.

Для каждого оборудования адаптер выбирает обработчик только по
`EquipmentTypeDefinition.behavior_key`, а не по пользовательскому имени.
Неизвестный behavior создаёт `unsupported_behavior` и блокирует построение;
объект не пропускается молча.

## ID и трассировка результатов

Каждый электрический узел и оборудование получают однозначный совместимый ID.
Коллизии, включая зарезервированный `GRID`, приводят к ошибке. Результат
адаптации содержит трассировку между каноническими ID и объектами legacy DTO,
чтобы будущие результаты можно было вернуть к исходному оборудованию без
поиска по названию.

Каждый вызов строит свежий `Network`. Он не становится редактируемой копией
модели и не сохраняется обратно как источник электрических связей.

## Физические линии

Для `LineSection` адаптер читает упорядоченные конструктивные участки и их
эффективные свойства. Физическая длина переводится из миллиметров в километры;
координаты `DiagramRoute` не доступны этому слою.

Расчёт блокируется, если хотя бы у необходимой записи:

- неизвестна длина;
- `length_confirmation != CONFIRMED`;
- отсутствуют подтверждённые `r1_ohm_per_km` или `x1_ohm_per_km`;
- составную линию нельзя свести к доказуемому последовательному эквиваленту.

В этом случае каноническое `None` не заменяется фиктивной длиной. Внутри
совместимого DTO может присутствовать технический `0.0` только потому, что
старый тип не умеет хранить `None`; одновременно обязательно записываются
`calculation_block_reason` и ошибка `line_data_unconfirmed`, запрещающие
расчёт.

Если все конструктивные участки имеют подтверждённые длины и удельные r1/x1,
адаптер суммирует точный последовательный эквивалент. Исходные марки, порядок
и типы остаются в `ElectricalModel`; DTO не становится их заменой.

Шинопровод без явных подтверждённых r1/x1 не маскируется под кабель. Для него
выдаётся отдельная блокирующая диагностика.

## Коммутационные аппараты и реклоузер

Выключатель, разъединитель и реклоузер адаптируются как switchable-ветви. Их
`normally_closed` выводится из нормального положения объекта, а выбранный
`OperatingState` учитывается активной топологией. Реклоузер остаётся отдельным
behavior и проходит дополнительные проверки двух портов и параметров.

Адаптер не делает радиального предположения «после открытого аппарата нет
питания». Компоненты и источники определяет `TopologyEngine` на полном графе.

## Пользовательская блокировка расчёта

`ProjectData.calculation_blockers` возвращает ошибки адаптера, а
`require_calculation_ready()` формирует русское сообщение с конкретным
объектом. Проект с неподтверждённой линией разрешено сохранять, открывать и
исправлять; запрещён только запуск расчёта, которому нужны эти данные.

Диагностический placeholder-снимок может быть построен для сохранения
целостного проекта при блокировке. Наличие такого `Network` не является
разрешением на расчёт: вызывающий код обязан пройти
`require_calculation_ready()`.

## Отображение статуса в редакторе

Рабочее место получает фактические `ProjectData.adapter_diagnostics`, включает
их в общую проверку проекта и передаёт на холст. Ошибка или предупреждение,
которые можно сопоставить с оборудованием, узлом или трассой по постоянному ID,
показываются встроенным красным либо жёлтым значком `!`; всплывающая подсказка
содержит сообщение и рекомендуемое действие.

Нижняя панель показывает фактическое число ошибок адаптации. Если проектный
контейнер не предоставляет диагностические данные, вместо ложного нуля
показывается «данные недоступны». Для выбранной трассы режим разработчика
выводит вычисленный по её `equipment_id` или `electrical_node_id` итог:
«заблокирован», «есть предупреждения», «ошибок адаптации для объекта нет» либо
«данные адаптера не переданы». Это только представление read-only диагностики;
оно не изменяет `core.Network` и не разрешает расчёт в обход
`require_calculation_ready()`.

## Миграция старых проектов

`import_legacy_network()` применяется только при чтении старого формата и
создаёт каноническую модель с детерминированными ID и явными маркерами
происхождения. Это отдельный путь миграции, а не обратный канал текущего
редактора.

После загрузки v7 каноническая модель снова является источником истины, и все
последующие совместимые представления строятся только из неё.

## Ограничения текущей реализации

- Старый DTO не представляет все последовательности, нейтрали, каталожное
  происхождение и смешанные конструктивные данные без потерь формы. Адаптер
  либо строит доказуемый эквивалент, либо блокирует расчёт.
- `require_calculation_ready()` запрещает расчёт по ошибкам адаптации, но сам
  расчёт ТКЗ нового поколения в Этапе 4 не реализуется.
- Обратная запись результатов и параметров из `core.Network` намеренно не
  поддерживается.
