# Поведение размещения оборудования

## Почему нужен явный реестр

Способ добавления оборудования на линию является электрическим правилом
редактора. Его нельзя определять по русскому названию, `type_id`,
`behavior_key`, числу портов, SVG-символу или координате отпускания мыши.
Такие эвристики ломают пользовательские типы и смешивают графику с
электрической моделью.

Единственный источник этого правила — одна capability `placement.*` в
`EquipmentTypeDefinition`.

## Типизированные варианты

`EquipmentPlacementKind` содержит четыре значения:

| Capability | Enum | Смысл |
|---|---|---|
| `placement.inline_series` | `INLINE_SERIES` | Разрезать линию и установить двухпортовый аппарат между двумя узлами |
| `placement.branch_attachment` | `BRANCH_ATTACHMENT` | Создать один узел отпайки и подключить явно выбранный порт |
| `placement.node_representation` | `NODE_REPRESENTATION` | Представить существующий электрический узел без создания оборудования |
| `placement.manual_selection` | `MANUAL_SELECTION` | Потребовать от пользователя явный сценарий подключения |

Если capability с префиксом `placement.` отсутствует, используется
`MANUAL_SELECTION`. Если их больше одной, определение отклоняется с русской
ошибкой как неоднозначное. Неизвестное значение `placement.*` также
отклоняется, а не угадывается.

Это правило относится к строгому конструктору реестра и ко всем новым
определениям. Свежие встроенные типы имеют явные capabilities: источники,
генераторы, трансформаторы и нагрузки — `placement.branch_attachment`; шина и
точка подключения — `placement.node_representation`; выключатель,
разъединитель и реклоузер — `placement.inline_series`.

Рабочий `EquipmentPlacementRegistry.for_model()` дополнительно содержит
ограниченную таблицу совместимости для фиксированных пар ID/версии встроенных
типов, сохранённых в старых проектах v7 до появления `placement.*`. Таблица
не анализирует имя, SVG, `behavior_key` или порты и никогда не применяется к
пользовательскому типу.

## `EquipmentPlacementRegistry`

Неизменяемый реестр строится из `EquipmentTypeDefinition` и индексируется
точной парой `(EquipmentTypeId, schema_version)`. Публичные операции:

- `resolve(type_id, schema_version)`;
- `resolve_definition(definition)`;
- `for_model(definitions)` для чтения старых встроенных определений v7;
- отображение `placements` только для чтения;
- детерминированные `signature` и SHA-256 `fingerprint`.

Порядок входных определений не влияет на сигнатуру. Повтор одной пары
ID/версии запрещён. Переданное в `resolve_definition()` определение должно
совпадать с зарегистрированным правилом.

Реестр не создаёт оборудование и не изменяет топологию. Он только выбирает
разрешённый командный сценарий; доменная команда повторно проверяет свои
электрические инварианты.

## Граница с другими реестрами

`placement.*` не заменяет:

- `TopologyBehaviorRegistry`, определяющий активную связность;
- `CalculationProjectionRegistry`, определяющий расчётное представление;
- каталожную запись с паспортными данными;
- `diagram_symbol_key`, отвечающий только за изображение.

Один тип может иметь, например, `placement.inline_series`,
`switch.position` и `equipment.availability`; эти независимые capabilities
описывают разные аспекты поведения.

## Применение в командах

`attach_equipment_to_line()` принимает только `BRANCH_ATTACHMENT` из рабочего
реестра `for_model()`. Generic последовательная вставка принимает только
`INLINE_SERIES`. Для `MANUAL_SELECTION` редактор не должен автоматически
разрезать линию: пользователь выбирает порт и электрическую операцию явно, а
доменная команда требует отдельное
`manual_placement_confirmed=True`. Без этого флага вставка отклоняется.

Пользовательский тип участвует на тех же основаниях, что и встроенный. Для
новой версии типа регистрируется отдельная пара `(type_id, version)`; правило
старой версии проекта не меняется задним числом.
