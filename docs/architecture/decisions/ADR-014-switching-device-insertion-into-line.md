# ADR-014: вставка коммутационного аппарата в линию

- Статус: принято на Этапе 4
- Дата: 2026-08-26

## Контекст

Коммутационный аппарат в середине линии должен реально разрывать путь при
положении OPEN. Если оставить один общий электрический узел по обе стороны
символа, отключение не изменит связность. Если считать аппарат маркером линии,
у него не будет собственных портов, ID, состояния и каталожных параметров.

Строгая `LogicalLine` одновременно требует непрерывной последовательности
своих `LineSection`. Она не должна скрыто перескакивать через отдельную ветвь
реклоузера.

## Решение

`insert_recloser_in_line()` выполняет одну доменную транзакцию:

1. физически делит выбранный `LineSection`;
2. создаёт два разных узла `J1` и `J2`;
3. оставляет левую часть в исходной `LogicalLine`;
4. создаёт для правой части отдельную `LogicalLine`;
5. присваивает обеим линиям общий `FeederId`;
6. создаёт настоящий `builtin.recloser` с портами `a` и `b`;
7. подключает его между `J1` и `J2`;
8. проверяет обе строгие линии и фиксирует всё одной транзакцией.

На уровне редактора та же проектная команда заменяет старую трассу двумя
трассами частей линии и добавляет графическое представление реклоузера.
Физический `offset_mm` и координаты символа передаются раздельно.

Пользователь запускает эту команду либо пунктом «Вставить реклоузер» на
физической трассе, либо перетаскиванием элемента реклоузера из библиотеки на
ВЛ/КЛ. Оба пути требуют подтверждения физического положения. Перемещение уже
вставленного символа остаётся графической операцией и не переносит аппарат в
другую линию.

Положение аппарата хранится в объектной модели и разреженном режиме, а не в
символе. `CLOSED` добавляет проводящий переход активного графа, `OPEN`
исключает только этот переход. Наличие питания определяется по всему графу с
учётом альтернативных источников.

## Отклонённые варианты

- один узел по обе стороны реклоузера;
- реклоузер как флаг или картинка на `LineSection`;
- скрытое сопротивление или фиктивная линия между страницами;
- сохранение обеих частей в одной `LogicalLine` через пропущенный аппарат;
- определение физического положения по пикселям;
- удаление оборудования при OPEN.

## Последствия

- коммутационное состояние действительно меняет активную топологию;
- два порта и два узла однозначно трассируются и сериализуются;
- паспортные данные, состояние и графическое положение сохраняются при OPEN;
- обе физические части остаются связаны пользовательским понятием фидера без
  нарушения строгой модели линии;
- один undo полностью удаляет вставку и возвращает исходную ветвь;
- тот же принцип применим к будущим двухпортовым аппаратам, но публичная
  составная команда Этапа 4 реализована именно для реклоузера;
- обратное удаление выполняется отдельной проверяемой командой только для
  реклоузера с сохранённым маркером вставки, совместимыми половинами и
  свободными служебными узлами; неоднозначный случай отклоняется без мутации;
- команда удаления доступна в контекстном меню такого символа и одной
  транзакцией удаляет аппарат и старые трассы, объединяет физические части и
  создаёт трассу восстановленной линии; undo возвращает исходную вставку.
