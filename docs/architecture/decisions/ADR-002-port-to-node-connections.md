# ADR-002: подключения port → electrical node

- Статус: принято и реализовано на Этапе 1
- Дата: 2026-08-25

## Контекст

Попарная модель «провод A—B» неоднозначна для шин, тройников и многоточечных соединений, а поля `node_from/node_to` внутри расчётной ветви не позволяют оборудованию владеть стабильными выводами. Графическая линия также не должна становиться электрическим фактом.

## Решение

Единственная domain-связь имеет вид:

```text
Connection(id, port_id, electrical_node_id)
```

`PortInstance` принадлежит ровно одному `EquipmentInstance`. В Этапе 1 каждый порт имеет ёмкость ровно одно подключение. Электрический многоточечный узел образуется несколькими `Connection`, указывающими на один `ElectricalNode`.

Внутренняя электрическая семантика оборудования не кодируется дополнительными `Connection`: её задаёт `behavior_key` типа и, для коммутационного аппарата, выбранный `OperatingState`.

## Инварианты

- Все ID существуют и имеют правильный runtime-тип.
- Строковые значения ID глобально уникальны; `GRID` запрещён.
- Роль порта допустима и уникальна у владельца.
- Kind и классы напряжения порта/узла совместимы, включая peer-порты общего узла.
- Повторное подключение single-capacity порта отклоняется атомарно.
- Слияние разных узлов выполняется только явной проверяемой командой.
- Удаление узла или оборудования с подключениями требует явного `cascade=True`.

## Последствия

- Шина и ответвление не требуют попарного полного графа проводов.
- Переименование и перемещение не меняют connectivity.
- Calculation adapter сам выводит `node_from/node_to` из портов.
- Будущая Diagram Model хранит маршрут отдельно и ссылается на `ConnectionId`.
- Topology engine обязан добавить внутренние рёбра оборудования; простого чтения списка `Connection` недостаточно.
