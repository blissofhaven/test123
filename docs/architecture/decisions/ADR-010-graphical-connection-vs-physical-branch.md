# ADR-010: графическое соединение и физическая ветвь

- Статус: принято на Этапе 4
- Дата: 2026-08-26

## Контекст

На однолинейной схеме одинаковая полилиния может означать две разные вещи:

1. изображение проводящего соединения частей одного электрического узла;
2. самостоятельную физическую ветвь оборудования между двумя узлами.

Если различать их по цвету, имени, символу или координатам, пересечение линий
может ошибочно создать связь, а ВЛ потеряет собственные порты, длину и
сопротивление. Один `port_id` у графического конца также недостаточен: для
физической ветви нужно одновременно знать её собственный порт и порт целевого
аппарата.

## Решение

В `DiagramRoute` вводятся два явных вида:

- `NODE_CONNECTION` — изображение одного `ElectricalNodeId`, без
  самостоятельного оборудования и без портов физической ветви;
- `EQUIPMENT_BRANCH` — изображение конкретного `EquipmentId` между двумя
  различными электрическими узлами.

`RouteEndpointAnchor` раздельно хранит:

- `branch_port_id` — собственный порт физической ветви;
- `target_port_id` — порт целевого аппарата;
- `electrical_node_id` — узел конца;
- `representation_id` и `anchor_key` — только графическую привязку.

У шины и обычного представления узла искусственный порт не создаётся.
Электрическое соединение определяется `ElectricalModel.Connection`, а не
`DiagramRoute`.

## Последствия

- простое графическое пересечение не меняет топологию;
- порт аппарата можно соединить с шиной без выдуманного порта шины;
- два порта физической линии однозначно сохраняют соответствие двум узлам;
- одна электрическая связь может иметь несколько графических представлений;
- низкоуровневое удаление `DiagramRoute` не изменяет оборудование;
  пользовательское
  действие «Удалить соединение или линию» обязано выполняться отдельной
  составной транзакцией, которая по явному виду трассы удаляет соответствующие
  `Connection` либо `LineSection` вместе с графикой;
- codec и валидатор обязаны отвергать смешение двух видов трасс.
