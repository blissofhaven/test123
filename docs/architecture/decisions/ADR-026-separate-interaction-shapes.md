# ADR-026: раздельные формы коллизий, выбора и трассировки

- Статус: принято на этапе UI-UX-1
- Дата: 2026-08-28

## Контекст

Видимый символ, его корпус, удобная область выбора, препятствие для линии и
зона электрического порта решают разные задачи. Если использовать один общий
bounding rectangle, увеличенный halo выбранности начинает блокировать
размещение, тонкий символ становится трудно выбрать, а трассировщик подходит
к корпусу слишком близко. После поворота такой общий прямоугольник также даёт
ложные совпадения и теряет смысловые стороны портов.

## Решение

Для каждого графического представления строить единый набор, но разные формы:

- `visual_bounds` — видимый габарит;
- `body_collision_shape` — запрещённая область твёрдого корпуса;
- `routing_obstacle_shape` — препятствие с отступом для маршрутов;
- `selection_shape` — удобная область hit-test и рамочного выбора;
- `port_connection_zones` — допустимые зоны подключения с ролью и `PortId`.

Overlay hover/selected, рамка группы и ручки редактирования не входят в
collision shape. Все формы поворачиваются вокруг одного anchor, а роли и ID
портов сохраняются. Геометрия строится в Qt-независимом слое из
`GraphicalRepresentation`; электрическая модель её не импортирует.

Для широкого поиска используется пространственный индекс по странице, затем
точная форма выбранной задачи. Выбор не должен использовать routing obstacle,
а collision-проверка не должна использовать selection halo.

## Отклонённые варианты

- один `boundingRect` для отрисовки, выбора, коллизий и маршрутизации;
- включать визуальные overlay в твёрдое тело;
- хранить экранные стороны портов вместо их смысловых ролей;
- определять коллизии непосредственно через дерево `QGraphicsItem` без
  headless-модели;
- зависеть от текущего масштаба при вычислении безопасного зазора.

## Последствия

- символ можно выбирать удобной областью, не увеличивая запрещённый корпус;
- линии получают собственный предсказуемый отступ от оборудования;
- выделение и hover не меняют результат collision detection;
- поворот сохраняет смысл портов и согласованно обновляет все формы;
- тесты и диагностика старых проектов выполняются без GUI;
- для нового класса символов необходимо определить или подтвердить несколько
  форм вместо одного прямоугольника;
- точные SVG-силуэты могут быть добавлены позднее без объединения задач форм.
