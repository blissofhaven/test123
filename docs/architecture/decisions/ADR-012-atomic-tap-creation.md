# ADR-012: атомарное создание отпайки

- Статус: принято на Этапе 4
- Дата: 2026-08-26

## Контекст

Создание отпайки затрагивает одновременно исходную физическую ветвь,
логическую линию, конструктивные участки, новый электрический узел, отходящую
линию и несколько графических трасс. Последовательная фиксация отдельных
шагов могла бы оставить линию разделённой наполовину либо создать узел без
отходящей ветви. Несколько шагов undo также не соответствуют одному действию
пользователя «Добавить отпайку».

## Решение

Отпайка создаётся одной составной командой.

На доменном уровне `create_tap_line()` работает с `_transaction_copy()`:

1. вызывает `split_line_section()`;
2. создаёт отходящую `LogicalLine` и её первый `LineSection` от того же узла;
3. проверяет порядок и ссылки;
4. одним `_commit_transaction()` заменяет состояние агрегата.

На уровне проекта `ProjectEditorController.create_tap()` выполняется внутри
`ProjectCommandHistory.execute()`. Тот же `ProjectDraft` содержит доменную
мутацию, удаление старой трассы, представление узла и три новые трассы. Перед
фиксацией одновременно проверяются электрическая модель, графические привязки и
снимки каталога.

Контекстное действие «Добавить отпайку» не запускает эту команду сразу после
диалогов. Холст сохраняет введённые параметры во временном состоянии и даёт
пользователю интерактивно построить отходящую ВЛ/КЛ с ручными точками. Только
завершённый черновик передаётся в `create_tap()`; `Esc` удаляет черновик без
изменения электрической модели, диаграммы или истории.

Графический клик не определяет физическое расстояние. Подтверждённый
`offset_mm` либо явное `None` для неизвестной длины передаются в доменную
операцию отдельно от `tap_x/tap_y`.

## Отклонённые варианты

- отдельные пользовательские команды «разделить», «создать узел», «создать
  ветвь» — допускают промежуточное некорректное состояние;
- специальный объект топологии `Tap` — ограничивает общий граф и дублирует
  обычный узел с тремя ветвями;
- вычисление offset по доле пиксельной трассы — смешивает физические и
  графические данные;
- попытка отдельно зафиксировать графику после уже изменённой модели — разрывает единый
  undo и может оставить ветвь без изображения.

## Последствия

- один `Ctrl+Z` полностью возвращает исходный `LineSection`, его ID и трассу;
- незавершённое либо отменённое рисование не требует undo, потому что проект
  ещё не был изменён;
- ошибка любого шага не изменяет проект;
- основная линия гарантированно продолжается через узел отпайки;
- несколько отпайек являются повторением той же общей операции графа;
- проект может сохранить честно неподтверждённые физические данные, но расчёт
  будет заблокирован;
- удаление отпайки является отдельной симметричной составной командой и
  объединяет главную линию только при однозначных совместимых данных.
