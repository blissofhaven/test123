# ADR-018: общий контракт последовательной вставки оборудования

- Статус: принято перед Этапом 4.6.1
- Дата: 2026-08-28

## Контекст

ADR-014 ввёл корректную двухузловую вставку реклоузера. Тот же электрический
закон нужен выключателю, разъединителю и пользовательским двухпортовым
аппаратам. Копирование отдельной команды для каждого названия типа привело бы
к разным проверкам, форматам marker и правилам удаления.

## Решение

Общим доменным контрактом становятся:

- `insert_series_equipment_in_line(...) -> InsertSeriesEquipmentResult`;
- `remove_series_equipment_from_line(...) -> RemoveSeriesEquipmentResult`.

Автоматическая вставка разрешена только зарегистрированному типу с capability
`placement.inline_series` и ровно двумя портами. Тип
`placement.manual_selection` допускается лишь после явного пользовательского
выбора, переданного как `manual_placement_confirmed=True`; по умолчанию флаг
ложен и операция запрещена. Роли берутся из порядка `PortDefinition` либо
передаются явной парой, которая обязана точно совпасть с двумя объявленными
ролями. SVG, имя и `behavior_key` не участвуют.

Операция создаёт два разных узла с
`creation_origin=automatic_inline_insertion`, делит строгую `LogicalLine` на
две линии одного `FeederId` и сохраняет marker `line_insertion`:

- `kind=inline_series`;
- ID и версию типа;
- упорядоченные `terminal_roles`;
- обе логические линии и оба узла;
- `FeederId`;
- физическое положение и его подтверждённость.
- признак явного подтверждения ручного сценария.

Удаление допускается только при совпадении marker с фактическим объектом,
совместимых половинах одного фидера и отсутствии третьих присоединений к двум
служебным узлам. Для `placement.manual_selection` требуется сохранённое
`manual_placement_confirmed=True`. Иначе операция атомарно отклоняется.

Старые методы реклоузера остаются совместимыми обёртками с прежними
контрактами результатов.
ADR-014 сохраняет историческое объяснение реклоузера, а это решение задаёт
общий закон.

## Отклонённые варианты

- определять возможность вставки по `type_id` или символу;
- создавать один общий узел по сторонам аппарата;
- разрешать тип с одним, тремя или неявно выбранными портами;
- удалять любой похожий двухпортовый объект без marker;
- объединять несовместимые половины или каталожные снимки с потерей данных.

## Последствия

- встроенные и пользовательские типы используют один алгоритм;
- `OPEN`/`CLOSED` влияет на путь через настоящий объект, а не через картинку;
- разбиение и объединение сохраняют порядок конструктивных участков;
- специализированный UI может развиваться без дублирования доменной логики;
- неизвестная физическая позиция остаётся явной и блокирует расчёт.
