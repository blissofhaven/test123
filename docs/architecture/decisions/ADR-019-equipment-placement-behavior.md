# ADR-019: поведение размещения задаётся capability типа

- Статус: принято перед Этапом 4.6.1
- Дата: 2026-08-28

## Контекст

Редактору нужно различать последовательную вставку, боковое присоединение,
представление узла и ручной выбор. Вывод этого поведения из названия, SVG,
`type_id`, `behavior_key` или числа портов был бы нестабилен для
пользовательских типов и смешивал бы электрические решения с графикой.

## Решение

`EquipmentPlacementRegistry` читает из каждого `EquipmentTypeDefinition`
ровно одну capability `placement.*` и возвращает типизированный
`EquipmentPlacementKind`:

- `placement.inline_series` → `INLINE_SERIES`;
- `placement.branch_attachment` → `BRANCH_ATTACHMENT`;
- `placement.node_representation` → `NODE_REPRESENTATION`;
- `placement.manual_selection` → `MANUAL_SELECTION`.

Отсутствие `placement.*` безопасно означает `MANUAL_SELECTION`. Несколько
таких capabilities или неизвестное значение отклоняются русской ошибкой без
догадки.

Свежие встроенные определения получают явные capabilities: источники,
генераторы, трансформаторы и нагрузки — `placement.branch_attachment`; шина и
точка подключения — `placement.node_representation`; выключатель,
разъединитель и реклоузер — `placement.inline_series`.

Для ранее сохранённых встроенных определений v7 без `placement.*` допускается
отдельный `EquipmentPlacementRegistry.for_model()`: он сопоставляет только
заранее зафиксированные пары системных ID/версии. Пользовательские типы без
явной capability всегда остаются `MANUAL_SELECTION`. Эта таблица
совместимости не использует имя, SVG, `behavior_key` или число портов.

Реестр неизменяем, индексируется точной парой `(EquipmentTypeId,
schema_version)` и предоставляет детерминированные `signature` и
`fingerprint`. Порядок регистрации не влияет на результат.

Реестр выбирает командный сценарий, но не меняет модель. Доменная команда
повторно проверяет число портов, роли, напряжение и топологические инварианты.
`MANUAL_SELECTION` может перейти к конкретной операции только после отдельного
явного подтверждения пользователя; для последовательной вставки это
`manual_placement_confirmed=True`.

## Отклонённые варианты

- список специальных `type_id` в GUI;
- сопоставление по `diagram_symbol_key`;
- использование `behavior_key` как правила размещения;
- распространение значений совместимости по умолчанию на пользовательские
  типы;
- первая найденная capability при конфликте;
- молчаливое автоматическое действие при отсутствии правила.

## Последствия

- пользовательская версия типа получает то же поведение, что встроенная;
- старые версии определений не меняются задним числом;
- правила размещения отделены от topology/projection registries;
- значение `MANUAL_SELECTION` по умолчанию предотвращает опасное
  автоматическое разбиение;
- fingerprint позволяет обнаружить изменение конфигурации реестра.
