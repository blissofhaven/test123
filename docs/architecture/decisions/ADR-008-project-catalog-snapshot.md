# ADR-008: снимок каталожной записи внутри проекта

- Статус: принято на Этапе 2.5
- Дата: 2026-08-25

## Контекст

Если экземпляр хранит только ссылку на общий каталог, обновление каталога
может незаметно изменить старый проект и сделать расчёт невоспроизводимым.
Копирование только эффективных чисел, наоборот, теряет источник и исходную
версию.

## Решение

Используются три уровня:

1. системный каталог только для чтения;
2. изменяемый пользовательский каталог;
3. неизменяемый локальный проектный снимок конкретной использованной версии.

Каждый слой имеет собственный постоянный `CatalogId`: системный,
пользовательский и проектный каталог-снимок. `CatalogEntrySnapshot` сохраняет
стабильный ID и версию записи, `source_catalog_id`, тип, категорию,
производителя, марку, паспортные/расчётные параметры, источник и дату.
Экземпляр отдельно
связывается со снимком через `CatalogBinding`, который хранит
`instance_overrides`, `calculated_values` и аудируемые `ParameterOverride`.
Все привязки проекта собраны в неизменяемом `ProjectCatalogSnapshots`. Название и
марка не используются как внутренний ключ.

## Последствия

- Изменение общего каталога не меняет сохранённый проект.
- Обновление экземпляра до новой версии является явной командой с diff и
  записью в историю.
- Проект открывается без доступа к исходной поставке каталога.
- Происхождение записи определяется парой `source_catalog_id` и
  `CatalogEntryId`, а не названием или маркой.
- Снимок и изменения экземпляра сериализуются раздельно в
  `catalog_snapshots` и проходят строгую проверку.
- Копирование экземпляра создаёт новый EquipmentId, но может ссылаться на тот
  тот же неизменяемый снимок.
- Полный интерфейс каталогов и онлайн-обновление в Этап 2.5 не входят.
