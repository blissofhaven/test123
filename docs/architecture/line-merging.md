# Объединение частей линии

## Назначение

Объединение является проверяемой обратной операцией для разделения линии,
удаления отпайки и снятия ранее последовательно вставленного оборудования.
Это не произвольная геометрическая команда: две визуально соседние трассы не
объединяются без доказанной электрической и физической совместимости.

## Схлопывание отпайки

`remove_line_tap(..., collapse=True)` объединяет соседние части основной
линии только если после удаления явно выбранных боковых ветвей:

- в узле остаются ровно два подключения;
- найдена ровно одна последовательная пара одной `LogicalLine`;
- тип и версия физического оборудования совпадают;
- класс напряжения, общие свойства, переопределения, примечания и расширения
  совместимы;
- узел не используется другими ветвями.

При нескольких оставшихся ветвях удаляется только выбранная боковая ветвь, а
узел сохраняется. Неоднозначность не разрешается эвристикой `parent/child`.

## Снятие последовательного аппарата

`remove_series_equipment_from_line()` сначала проверяет маркер вставки,
реальные подключения двух портов, служебные узлы, общий `FeederId` и обе
логические линии. Затем одной транзакцией:

1. удаляет аппарат и его подключения;
2. объединяет два служебных узла;
3. возвращает правые участки в левую `LogicalLine`;
4. удаляет правую логическую линию;
5. схлопывает соседние физические части в новый `LineSection`.

Специализированное удаление реклоузера следует тому же закону.

## Конструктивные участки

Новый `LineSection` получает упорядоченную конкатенацию
`left.construction_segments + right.construction_segments`. Записи разных
марок не усредняются и не превращаются в дополнительный электрический узел.
Существующие ID неизменённых записей сохраняются; новый ID получает только
сама объединённая электрическая ветвь и необходимые порты/подключения.

Неподтверждённые длины и сопротивления остаются неподтверждёнными. Объединение
не повышает качество данных и не делает заблокированный расчёт разрешённым.

## Политика каталожных привязок

`ProjectEditorController._merge_catalog_bindings()` сравнивает содержимое
`CatalogBinding` без зависящего от экземпляра `equipment_id`:

- если привязок нет у обеих частей, новая ветвь остаётся без привязки;
- если привязки есть у обеих частей и полностью совпадают, создаётся одна
  привязка к новому `EquipmentId`;
- если привязка есть только у одной части, объединение блокируется;
- если различаются `CatalogEntrySnapshot`, `instance_overrides`,
  `calculated_values`, `parameter_overrides` или `extensions`, объединение
  блокируется.

Данные не выбираются по принципу «левая часть важнее» и не смешиваются.

## Атомарность и ID

`ElectricalModel`, `DiagramDocument` и `ProjectCatalogSnapshots` фиксируются
одним шагом истории. До фиксации проверяются ссылки, уникальность ID,
непрерывность логических линий и графические цели. При ошибке не остаётся
частично удалённого аппарата или половины линии.

Один undo восстанавливает исходные две ветви, узлы, аппарат, трассы и
каталожные привязки с прежними ID. Повтор операции создаёт тот же логический
результат, но новые сущности получают новые постоянные ID, если они не были
заданы командой явно.
