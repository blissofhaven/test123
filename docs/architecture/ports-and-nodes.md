# Электрические порты и узлы

## Нормализованная модель

Связность представлена тройкой сущностей:

```text
EquipmentInstance
    └─ PortInstance -- Connection --> ElectricalNode
```

`Connection` является единственной нормализованной записью подключения порта
к эквипотенциальному узлу. У оборудования нет полей `parent`, `child`,
`previous` или `next`, а узел не хранит ограниченный список «вход/выход».
Любое число портов одного электрического типа может ссылаться на один узел;
инцидентные ветви выводятся из полного набора `Connection`.

## Что хранится у порта

`PortInstance` хранит только постоянные факты конкретного экземпляра:

- `PortId`;
- `EquipmentId` владельца;
- стабильную роль, например `hv`, `lv`, `a`, `b`, `from`, `to` или
  `terminal`.

Остальной контракт определяется без дублирования через `PortDefinition`
версии типа оборудования:

| Свойство | Фактический источник |
|---|---|
| назначение и сторона | `role` и `display_name` |
| электрический тип | `kind_id` |
| группа напряжения | `voltage_group` |
| разрешённые классы | `allowed_voltage_class_ids` |
| обязательность | `required` |
| число узлов | `max_connections`, сейчас строго `1` |
| фактический класс | `EquipmentInstance.voltage_class_by_group` |
| состояние подключения | наличие `Connection` для `PortId` |

Положение точки на символе и направление графического выхода относятся к
GUI. `SymbolPortAnchor` вычисляется по роли и геометрии символа, а выбранная
точка записывается в `RouteEndpointAnchor.anchor_key`. Поворот символа меняет
графическое направление, но не меняет роль `hv` на `lv` и не создаёт новый
порт.

## Один порт — один узел

`PortDefinition.max_connections` в нормализованной модели обязан быть равен
единице. `ElectricalModel.add_connection()` дополнительно проверяет, что для
порта ещё нет связи. Многоточечное соединение моделируется не несколькими
узлами одного порта, а одним общим узлом с любым количеством подключённых
портов.

Это правило устраняет неоднозначность вида «к какому из двух узлов относится
напряжение порта» и позволяет сохранять стабильный `ConnectionId` при
переподключении конца.

## Электрический узел

`ElectricalNode` содержит:

- постоянный `ElectricalNodeId`;
- имя и примечание;
- `PortKindId`;
- необязательный объявленный класс напряжения;
- расширения для происхождения узла, например физического положения отпайки.

Шина, соединительный кружок и точка отпайки — разные графические
представления этой сущности. Один узел может иметь несколько представлений и
на одной, и на разных страницах. В электрической модели от этого остаётся один
ID.

## Совместимость

Перед подключением `_check_connection_compatibility()` проверяет:

1. равенство `PortKindId` порта и узла;
2. отсутствие конфликта известного класса порта и узла;
3. попадание класса узла в `allowed_voltage_class_ids`, если ограничение
   задано;
4. отсутствие в узле портов разных известных классов;
5. отсутствие другого порта того же оборудования в этом узле.

`connect_ports()` сначала конструирует все будущие записи и проверяет их ID и
совместимость, а затем фиксирует изменение. Если ни у одного порта ещё нет
узла, создаётся один новый узел. Его класс выбирается из известного класса
любого из двух портов. Два разных известных класса приводят к отказу.

Если один порт уже подключён, второй присоединяется к существующему узлу.
Если оба принадлежат разным узлам, автоматического слияния нет: вызывающий код
должен явно применить `merge_nodes()`, которое повторно проверяет напряжения и
самопетли.

## Переподключение

`reconnect_port()` переносит существующую запись на другой узел, сохраняя:

- `EquipmentId`;
- `PortId`;
- `ConnectionId`.

Проверка новой цели выполняется на транзакционной копии после временного
удаления старой записи. При ошибке исходное подключение остаётся неизменным.
Автоматическое удаление освободившегося узла не выполняется без отдельной
команды: это защищает другие графические представления и межсхемные ссылки.

На холсте выбранная трасса физической ветви показывает экранные маркеры её
начала и конца. Перетаскивание такого маркера запускает режим
переподключения именно собственного `branch_port_id`, а не создаёт новую
ветвь. Успешная команда одновременно:

- сохраняет `EquipmentId`, `PortId`, `ConnectionId` и `DiagramRouteId`;
- заменяет электрический узел только выбранного конца;
- обновляет `RouteEndpointAnchor` и локальную ортогональную геометрию;
- образует один шаг undo.

Обычный занятый порт оборудования также можно переподключить через его
контекстное действие. Если целью является середина ВЛ/КЛ, команда
`reconnect_port_to_tap()` разрезает выбранный `LineSection`, создаёт настоящий
узел отпайки и переносит в него существующий `Connection` с тем же ID. Конец
одной физической линии пока нельзя таким способом присоединить к середине
другой: это требует отдельной однозначной операции объединения линейных
маршрутов.

## Шины

Несекционированная шина — одно представление одного `ElectricalNodeId`.
`RouteAnchorKind.BUS` обозначает лишь графическую точку на её изображении.
У шины не создаётся искусственный порт на каждое присоединение, поэтому
перемещение точки вдоль шины не меняет электрическую модель.

Секционирование должно создавать два разных узла и реальный коммутационный
аппарат между ними. Простой визуальный разрыв или растяжение шины этого не
делает.

## Напряжение: объявленное и эффективное

Объявленный класс хранится у узла, а класс порта определяется по группе
напряжения оборудования. При создании общего узла для известного и
неизвестного портов известный класс записывается в новый узел. Для новой
физической линии класс выводится из её конечных узлов; конфликт блокирует
команду.

`TopologyEngine` дополнительно строит производные зоны напряжения и
диагностирует конфликты. Эта производная информация не записывается обратно в
порты и не превращается во второй источник истины.

## Явные границы контракта

`PortInstance` намеренно не дублирует назначение, электрический тип и
ограничения из версионированного `PortDefinition`. Автоматическое изменение
`declared_voltage_class_id` уже существующего неизвестного узла также не
выполняется как скрытая мутация: эффективный класс выводится из подключённых
портов и топологической диагностики, а закрепление объявленного класса должно
быть отдельным подтверждаемым электрическим действием.

Полноценное межстраничное взаимодействие и пользовательская операция
секционирования шины относятся к следующим этапам; модель постоянных ID и
нескольких графических представлений уже не требует для них второго
электрического графа.
