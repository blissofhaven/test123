# Этап B5 — Панель свойств по модели параметров

**Трек:** B · **Исполнитель:** Sol · **Зависит от:** A3 · **Оценка:** 4–5 дней

## Цель

Панель свойств должна строиться **по модели параметров**, а не по списку полей
в коде. Тогда новый тип оборудования появляется в интерфейсе сам, без правки
GUI.

## Входной контроль

Проверить **по коду**, а не по отчёту A3:

- модель параметров возвращает для типа оборудования: группы, поля,
  обязательность, единицу, диапазон, происхождение значения;
- запись значения возвращает ошибку валидации с названным параметром и
  диапазоном;
- пользовательское поле добавляется и переживает сохранение.

Если контракта нет — `docs/work-verification/B5-blocked.md` и остановиться.
Не достраивать модель параметров внутри этапа B5.

## Граница этапа

**Разрешено:** `rza_calc/gui/**`, GUI-тесты, документация.

**Запрещено:** `core/**`, `domain/**`, `adapters/**`, `io/**`. Если чего-то
не хватает в модели параметров — это запрос к A3, а не правка домена.

**Числа:** не меняются.

## Состав работ

1. Панель строится по группам из модели, порядок полей — из модели.
2. Обязательные незаполненные поля выделены; видно, что именно блокирует
   расчёт.
3. У необязательного поля видно принятое по умолчанию значение и его влияние
   («ΔPк не задано — активное сопротивление принято нулевым»).
4. Происхождение значения: вручную / из справочника / по умолчанию — видно
   без наведения.
5. Пользовательские поля: добавление, единица, примечание, удаление.
6. Массовое редактирование нескольких выбранных объектов одного типа.
7. Ошибка валидации показывается рядом с полем, а не общим окном.

## Критерии готовности

* Новый тип оборудования отображается в панели без правки GUI.
* Невозможно сохранить значение вне допустимого диапазона.
* Видно, какие поля переопределены относительно каталожной записи.
