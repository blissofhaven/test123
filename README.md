> актуальности, входной валидации и смешения расчётных ступеней напряжения.
> Для выбранного узла добавлены четыре вида КЗ с явными эквивалентами
> последовательностей. Нормативно верифицированная методика, двигательная
> подпитка, временные составляющие и промышленная приёмка ещё не реализованы.
> Старые расчёты защит автоматически на новый путь не переводятся.
> Результат нельзя использовать для
> выпуска инженерной документации без независимой проверки.

## Четыре вида КЗ — 07.09.2026

Во вкладке «КЗ» можно выбрать трёхфазное, двухфазное, однофазное на землю
или двухфазное на землю повреждение. Показаны фазные токи и остаточные
напряжения, 3I0, допущения и причина недоступности расчёта.
Проверочный проект: `rza_calc/examples/four_fault_types.json`.
Для двухфазного КЗ требуется обоснованное Z2; для повреждений на землю —
также Z0 и схема нулевой последовательности. Отсутствующие параметры
не подставляются автоматически.
Порядок запуска, поля, проверки и ограничения — в
[отчёте расширения](docs/work-verification/four-fault-types.md).

## Что уже работает

* **Каноническая электрическая модель** `ElectricalModel`: equipment instances,
  принадлежащие им typed ports, equipotential electrical nodes, connections и
  operating states. Связность хранится по стабильным ID и не зависит от имён,
  SVG или координат.
* **Topology Engine** `rza_calc.topology`: строит active multigraph напрямую
  из Domain Model, учитывает OPEN/CLOSED и IN_SERVICE/OUT_OF_SERVICE, находит
  компоненты, острова, источники, пути, кольца и параллельные ветви. Источники
  не объединяются через искусственный `GRID`; 3W трансформатор остаётся одной
  звездой без ложного кольца.
* **Наследование номинального напряжения**: отдельные voltage zones получают
  evidence от узлов, оборудования и логических линий. Трансформатор связывает
  active topology, но разделяет 110/35/10 кВ. UNKNOWN и CONFLICT не
  подменяются догадкой.
* **Постоянная диагностика**: immutable snapshot содержит typed
  Error/Warning/Info с точными EquipmentId/PortId/ElectricalNodeId. Unknown
  behavior и незавершённые ветви обрабатываются fail-closed.
* **Логические линии и физические участки**: `LogicalLine` объединяет
  упорядоченные `LineSection`, а каждый участок является самостоятельным
  двухполюсным equipment. Длина хранится целым числом миллиметров; параметры
  разрешаются в порядке «default типа → наследование линии → override
  участка». Разбиение участка, создание и удаление отпайки выполняются
  атомарными domain-командами через явный общий `ElectricalNode`.
* Расширяемый registry типов оборудования и классов напряжения. Встроены
  220 / 110 / 35 / 10 / 6 / 0,4 кВ; новые классы добавляются данными, а не
  изменением закрытого enum. Для новых сущностей используются отдельные типы
  `builtin.recloser`, `builtin.line_section.overhead` и
  `builtin.line_section.cable`; реклоузер не маскируется под обычный QF.
* **Каталоги оборудования**: immutable системный каталог и пользовательский
  каталог из immutable-записей уже реализованы на уровне Domain/API. Есть
  категория реклоузеров, instance overrides, создание параметров экземпляра и
  сохранение экземпляра как пользовательской записи. При создании КЛ/ВЛ можно
  вручную заполнить марку, сохранить её в справочник проекта и выбирать для
  следующих линий. Длина и число параллельных цепей задаются для каждого участка.
* **Формат проекта v7** хранит каноническую электрическую модель, графическое
  представление схемы, снимки справочников и встроенный
  пользовательский каталог без параллельной копии расчётного `Network`.
  Строгий loader отклоняет неизвестные поля, повторные ID и висячие ссылки,
  читает v1–v7 и мигрирует старые версии; `save_project()` всегда пишет v7
  атомарно и создаёт резервную копию перед преобразованием старого файла.
  Исходный файл при обычном открытии не изменяется. Operating state хранит
  OPEN/CLOSED отдельно от IN_SERVICE/OUT_OF_SERVICE.
* Расчётный адаптер каждый раз строит новый `core.Network` и trace от Domain ID
  к расчётным объектам. Существующие составные legacy-ветви сохраняются как
  явно помеченное compatibility equipment: программа не выдумывает отдельные
  QF/ТТ, которых не было в исходных данных.
* **Редактор однолинейной схемы** на `QGraphicsScene`: библиотека отдельных
  электрических элементов, дерево проекта, холст, инспектор свойств, журнал и
  диагностика. Поддержаны масштабирование относительно курсора,
  панорамирование, сетка и привязка, рамочное и групповое выделение,
  перемещение, копирование, вставка, дублирование, безопасное удаление,
  отмена/повтор и отдельный режим анализа. Координаты и подписи хранятся только
  в `DiagramDocument` и не меняют электрическую связность.
* Добавление элемента выполняется одной командой: создаются оборудование,
  его электрические порты и графическое представление. История проекта
  атомарно восстанавливает электрическую модель, схему и каталожные снимки.
  Неподключённый черновик можно сохранить и продолжить редактировать, но до
  подключения обязательных портов расчёт честно блокируется.

* Модель ПС как граф: узлы (шины, расчётные точки) + ветви (система,
  трансформаторы, линии, вводы, СВ). Защита ставится на ветвь — отсюда
  программа сама знает, кто ниже кого по сети.
* **Режимы сети** — с самого начала, а не как надстройка. Любой расчёт есть
  функция от (сеть, режим). Уставка выбирается по наиболее тяжёлому режиму,
  чувствительность проверяется по самому лёгкому, и это разные режимы.
* Токи КЗ через матрицу узловых проводимостей: параллельная работа
  трансформаторов через включённый СВ и обратное направление питания
  учитываются автоматически, без особых случаев в коде.
* МТЗ, ТО, ОЗЗ; чувствительность в основной зоне и зоне резервирования;
  вторичные уставки через ТТ с округлением по шкале терминала.
* Селективность: программа сама строит иерархию защит **отдельно для каждого
  режима**, назначает выдержки снизу вверх и проверяет ступень.
* **Пошаговый протокол части расчётов**: что считаем / зачем / исходные /
  формула / подстановка / результат / источник. После safe-hardening каждый
  запуск также получает отпечатки модели и методики и версии приложения,
  ядра и алгоритма. Полный машиночитаемый граф зависимостей каждой цифры и
  генерация Word/Excel относятся к следующим этапам.
* **Генераторы вместо системы бесконечной мощности**: ГТГ/ГПА задаются мощностью
  и x″d, состав работающих машин — это режим. Токи КЗ по всей сети меняются
  вместе с ним.
* **Трёхобмоточный трансформатор** пока поддержан как упрощённая звезда из
  попарных Uк. Это переходная модель: распределение потерь, РПН, группы
  соединения, нейтрали и отдельная физическая модель автотрансформатора ещё
  не прошли нормативную и инженерную верификацию.
* **Токораспределение**: при двух параллельных ВЛ, вводах или трансформаторах
  через каждый идёт своя доля тока КЗ. Считается из той же обращённой матрицы.
  Без этого уставки на параллельных элементах завышаются вдвое.
* **Физическая сторона ТТ** задаётся узлом `ct_node` и не меняется при
  реверсе питания. Рабочие токи и токи КЗ приводятся к напряжению именно
  этой стороны. Для старого файла сторона фиксируется при загрузке по прежней
  ориентации ветви и записывается явно при следующем сохранении.
* Недостоверные исходные данные блокируют расчёт: потерянная методика,
  неизвестный аппарат в режиме, неверный коэффициент ТТ, напряжение или
  диапазон параметров больше не проходят как обычные предупреждения.
* Уставка выше диапазона терминала получает статус ошибки и не сохраняется
  как принятое значение. Отключённая МТЗ исключается из селективности, а
  смена направления иерархии между режимами возвращает инженерский статус
  «не определено» вместо аварийного завершения программы.
* Ступени 220 / 110 / 35 / 10 / 0,4 кВ.
* **Физическая структура отдельно от расчётного графа**: ГТЭС/ПС/РП/КТП →
  уровень напряжения → ячейка → оборудование. Один аппарат может быть связан
  с несколькими ячейками: линия — с двумя подстанциями, АТ — со сторонами
  ВН/СН/НН. Связи с узлами, ветвями и нагрузками расчётной схемы явные.
* Проект — один версионированный JSON-файл канонического формата v7. Физическая структура
  навигации пока сохраняется отдельно для совместимости, а источником
  электрической истины служит `electrical_model`.
* Трёхобмоточный трансформатор сохраняется как один физический аппарат.
  Внутренняя звезда и три расчётных луча создаются при загрузке и не попадают
  в файл как самостоятельное оборудование.
* **Рабочий экран PySide6 с интерактивной SVG-схемой**: выбор режима,
  карточки генераторов, суммарная мощность, дерево сети, автоматически
  построенная обзорная схема, свойства выбранного объекта, токи КЗ, уставки,
  проверки и селективность. Подстанции строятся компактными типовыми блоками,
  линии прокладываются ортогонально и не объединяются с параллельной цепью.
  Колесо мыши меняет масштаб, перетаскивание двигает лист, двойной щелчок по
  подстанции приближает её, а кнопки возвращают общий вид или 100 %.
  Каждый выключатель, трансформатор, участок шин и линия остаётся отдельным
  SVG-объектом и открывает свою карточку справа. Данные берутся из открытого
  JSON-проекта, а кнопка «Пересчитать» вызывает то же расчётное ядро, что и
  командная строка.
* На схеме КТП предусмотрены два вводных места и выключатели. Если в проекте
  задан только один питающий фидер, второй показывается зелёным как
  `Резерв (не задан)` и **не участвует в расчёте**. После добавления второй
  реальной линии заглушка автоматически заменяется её трассой.
* Пользовательский режим можно собрать переключателями генераторов. Пока он
  существует в памяти до закрытия программы; безопасное сохранение изменений
  будет добавлено вместе с редактором проекта.

## Чего ещё нет

Этап 4 завершил базовые электрические соединения, ортогональные трассы,
отпайки и реклоузеры. Пока отсутствуют полноценные многостраничные подсхемы с
межсхемными портами, окончательная система сменных символов, полный
браузер/редактор каталогов и отраслевое наполнение.

Расчётное ядро пока не содержит полноценных сетей обратной и нулевой
последовательностей, однофазных и двухфазных-на-землю КЗ, двигательной
подпитки, ударного/апериодического/отключаемого тока, теплового импульса,
разреженного решателя и нормативно подтверждённой промышленной методики.
`Iк(2)` выдаётся только как явно помеченная оценка `√3/2·Iк(3)` при допущении
`Z2 = Z1`.

Также не реализованы производственные модули ДЗТ, ЗДЗ, УРОВ, АПВ, АВР, ЗМН,
полные защиты двигателей/генераторов и генераторы отчётов Word/Excel/PDF.

## Запуск

Для интерфейса в Windows дважды щёлкните `ЗАПУСК.bat` или выполните:

```
python -m rza_calc.gui
python -m rza_calc.gui C:\Проекты\мой-проект.json
```

Первый запуск открывает учебный нефтепромысел с ГТЭС и 34 площадками.
Дальше программа открывает последний успешно открытый или сохранённый проект.
Если он удалён, недоступен или относится к старым встроенным примерам,
открывается нефтепромысел. В папке `rza_calc/examples` оставлен только
`oilfield_gtes.json`; старые схемы находятся в технических данных тестов
`tests/fixtures/legacy_projects`.

Командная строка остаётся доступна:

```
python -m rza_calc example report          # Нефтепромысел с ГТЭС
python -m rza_calc rza_calc/examples/oilfield_gtes.json report
```

Команды: `check`, `modes`, `sc`, `table`, `feeder <id>`,
`explain <id> <защита>`, `selectivity`, `report`.

Пример: `python -m rza_calc <проект> explain F1 МТЗ` — полный вывод уставки
МТЗ фидера-1 со всеми промежуточными расчётами.

## Требования

Python 3.10+, numpy, PySide6. После установки зависимостей интернет не нужен.

## Тесты

```
pytest -q                 # если pytest установлен
python tests/run_tests.py # если нет
```

После safe-hardening добавлены отдельные регрессии аудита и проверки
актуальности результата. В среде независимой доработки пройдены **448
не-GUI тестов**. Ещё 44 offscreen/GUI-теста требуют установленный PySide6 и
должны быть повторены на рабочем Windows-ПК. Ключевые тесты сверяются с
независимым аналитическим/Ybus-расчётом, а не только с прежним результатом.

## Важное предупреждение

`rza_calc/data/methodology_default.json` — **заглушка**. Коэффициенты
отстройки, возврата, самозапуска, ступень селективности и критерии
чувствительности в ней не согласованы ни с какой методикой и не могут
применяться на реальном объекте. Замените их значениями, принятыми на вашем
предприятии или в проекте, и заполните поле `source`.

То же относится к `data/cables.json`: удельные индуктивные сопротивления —
ориентировочные, удельные ёмкостные токи программа вообще не подставляет
сама и требует задавать по каталогу.

Программа считает и проверяет. Ответственность за уставки остаётся на
инженере.
