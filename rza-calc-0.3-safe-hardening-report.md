# Безопасное усиление расчётного пути после аудита 4.4

Дата независимой доработки: **28.08.2026**.
Версия приложения: **0.3.1-safe-hardening**.
Версия переходного ядра: **legacy-positive-sequence-2**.
Версия алгоритма: **dense-ybus-v2**.

## Назначение

Эта доработка закрывает опасные ошибки, при которых приложение могло показать
правдоподобное число для устаревшей топологии или физически недопустимых
исходных данных. Она также устраняет подтверждённое смешение физических и
средних расчётных напряжений в многоступенчатом контрольном примере.

Это **не** завершённое промышленное ядро ТКЗ и не завершение всего этапа 4.6.
Существующий решатель остаётся переходным решателем только прямой
последовательности с плотной матрицей Ybus.

Исходные документы `docs/calculation-audit/**` сохранены как неизменяемая
базовая фиксация состояния до исправлений. Результаты после доработки находятся
в этом каталоге.

## Что исправлено

1. **Актуальность топологии и расчёта**
   - введён детерминированный SHA-256 отпечаток электрического содержимого;
   - кэш топологии больше не определяется только номером ревизии;
   - divergent history после undo/redo не получает старый snapshot;
   - `ProjectData.network` пересобирается по содержимому;
   - GUI больше не хранит старую mutable-ссылку `self.net` и перед расчётом
     получает актуальный `project.network`;
   - `CalculationProjection` проверяет отпечаток модели и реестра обработчиков.

2. **Валидация исходных данных**
   - блокируются NaN и Infinity;
   - блокируется отрицательная мощность КЗ источника;
   - при одновременных противоречивых Sкз и Iкз требуется явный способ задания;
   - блокируются отрицательные R/X обычной ВЛ/КЛ;
   - блокируется отрицательный Uk обычного двухобмоточного трансформатора;
   - служебный отрицательный луч подтверждённой модели 3W отделён от обычного
     пользовательского 2W-трансформатора.

3. **Модель напряжений**
   - сопротивление оборудования рассчитывается на его физической/паспортной
     ступени;
   - приведение между ступенями выполняется по согласованным физическим
     напряжениям;
   - среднее расчётное или предаварийное напряжение применяется отдельно для
     ЭДС/напряжения до КЗ;
   - автоматический подбор «ближайшей» ступени среднего напряжения запрещён;
   - новые поля семантики напряжения и выбора источника сохраняются при
     legacy round-trip.

4. **Результаты и происхождение**
   - каждый запуск получает `CalculationCase`;
   - сохраняются отпечатки модели и методики;
   - сохраняются версии приложения, ядра и алгоритма;
   - результат умеет определять статус `current/stale`;
   - CLI показывает версии и сокращённые отпечатки;
   - все текущие результаты заметно маркируются как предварительные.

5. **Токораспределение**
   - добавлен ориентированный комплексный коэффициент тока ветви;
   - добавлен комплексный ток ветви в направлении `node_from → node_to`;
   - старый API модуля тока оставлен только для совместимости существующего
     расчёта РЗА.

6. **Двухфазное КЗ**
   - округлённый коэффициент 0,866 заменён на точное `sqrt(3)/2`;
   - результат явно помечен как оценка только для частного допущения `Z2=Z1`;
   - интерфейс и протокол больше не называют это полноценным общим расчётом
     двухфазного КЗ.

7. **Диагностика**
   - добавлены предметные коды `INVALID_INPUT`, `NOT_ENERGIZED`,
     `NUMERIC_FAILURE`;
   - контролируются конечность матрицы и решения;
   - вычисляется число обусловленности, при большом значении выдаётся
     предупреждение;
   - отсутствие X/R, двигательная подпитка и ориентировочные параметры линий
     отображаются как явные ограничения.

## Контрольный пример ГТЭС → КТП

После исправления модель напряжений совпадает с независимым расчётом в омах и
относительных единицах:

| Величина | Ожидается | После исправления |
|---|---:|---:|
| RΣ*, о.е. | 1,4121551911 | 1,4121551911 |
| XΣ*, о.е. | 8,0361436299 | 8,0361436299 |
| |ZΣ*|, о.е. | 8,1592761152 | 8,1592761152 |
| Iк3 на 0,4 кВ, кА | 17,6899966687 | 17,6899966687 |
| ток ветви 10 кВ, кА | 0,7075998667 | 0,7075998667 |
| ток ВЛ-110, кА | 0,0643272606 | 0,0643272606 |
| ток стороны генератора 10,5 кВ, кА | 0,6739046350 | 0,6739046350 |

Проверка относится к синтетическому трёхфазному металлическому КЗ с
оговорёнными исходными данными. Она не является нормативной аттестацией всей
методики.

## Что осталось нерешённым

- нет полноценных схем обратной и нулевой последовательностей;
- Iк2 остаётся явно маркированной оценкой, а не общим расчётом;
- двигательная подпитка не рассчитывается, только выдаётся предупреждение;
- полный комплексный вклад каждого источника ещё не включён в `ProjectResult`;
- существующие защиты продолжают использовать совместимый модуль тока, хотя
  новый комплексный API уже доступен;
- решатель продолжает использовать плотное `numpy.linalg.inv`;
- нет разреженной факторизации и расчётного SLA для 5000 узлов;
- нет нормативно утверждённого профиля формул и коэффициентов;
- default-методика и часть справочника линий остаются заглушками;
- модели 3W, автотрансформатора, РПН, групп соединения и нейтралей остаются
  неполными;
- нет ударного, апериодического, отключаемого и теплового тока;
- нет промышленного Word/Excel/PDF-отчёта;
- GUI/offscreen тесты должны быть повторены на Windows с PySide6.

## Режим применения

До завершения перечисленных работ приложение можно применять для разработки,
обучения и ограниченных проверочных трёхфазных расчётов с независимым
пересчётом. Использование для выпуска уставок, выбора оборудования или
производственной документации без инженерной проверки запрещено.
